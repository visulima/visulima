# Custom Storage Backends

Create custom storage backends by extending `AbstractBaseStorage` (exported as `BaseStorage`) or implementing custom `MetaStorage` for advanced use cases.

## Overview

Visulima Storage provides two base classes for customization:

- **`AbstractBaseStorage`** - Base class for creating custom storage backends
- **`MetaStorage`** - Base class for custom metadata storage implementations

## Creating a Custom Storage Backend

### Extending AbstractBaseStorage

`BaseStorage` is exported from the package root as `AbstractBaseStorage`. A subclass must provide the `meta` storage and implement six abstract methods; everything else has a working default you can override.

```typescript
import type { Readable } from "node:stream";

import type { FileInit, FilePart, FileQuery } from "@visulima/storage";
import { AbstractBaseStorage, File, LocalMetaStorage } from "@visulima/storage";

// `FileReturn` (what `get()` resolves to) isn't exported from the root; derive it.
type FileReturn = Awaited<ReturnType<AbstractBaseStorage["get"]>>;

interface MyStorageOptions {
    apiKey: string;
    endpoint: string;
}

class MyCustomStorage extends AbstractBaseStorage<File> {
    public static override readonly name: string = "my-custom-storage";

    // Where upload metadata lives. Any MetaStorage works (LocalMetaStorage, MemoryMetaStorage, your own).
    protected meta = new LocalMetaStorage<File>({ directory: "./upload-meta" });

    private readonly apiKey: string;
    private readonly endpoint: string;

    public constructor(config: MyStorageOptions) {
        super({
            maxUploadSize: "100MB",
            allowMIME: ["*/*"],
            // ... other BaseStorageOptions
        });

        this.apiKey = config.apiKey;
        this.endpoint = config.endpoint;
    }

    public async create(init: FileInit): Promise<File> {
        const file = new File(init);

        await this.validate(file); // maxUploadSize / allowMIME / file name / custom rules

        file.bytesWritten = 0;
        file.status = "created";

        await this.saveMeta(file);
        await this.onCreate(file);

        return file;
    }

    public async write(part: FilePart | FileQuery | File): Promise<File> {
        const file = await this.getMeta(part.id);

        if (!("body" in part) || !part.body) {
            return file; // metadata-only call (e.g. a HEAD-style offset check)
        }

        file.bytesWritten = await this.uploadChunk(file.id, part.start, part.body);
        file.status = file.bytesWritten === file.size ? "completed" : "part";

        await this.saveMeta(file); // persist the offset after every chunk
        // Don't call onComplete here: the upload handlers call it once the upload completes.

        return file;
    }

    public async get(query: FileQuery): Promise<FileReturn> {
        const file = await this.getMeta(query.id);
        const content = await this.download(file.id);

        return { ...file, content, size: content.length } as FileReturn;
    }

    public async delete(query: FileQuery): Promise<File> {
        const file = await this.getMeta(query.id);

        await this.remove(file.id);
        await this.deleteMeta(file.id);
        await this.onDelete(file);

        return { ...file, status: "deleted" } as File;
    }

    public async copy(source: string, destination: string): Promise<File> {
        /* server-side copy in your backend, then save metadata for `destination` */
    }

    public async move(source: string, destination: string): Promise<File> {
        const moved = await this.copy(source, destination);

        await this.delete({ id: source });

        return moved;
    }

    // Backend calls (placeholders for your SDK)
    private async uploadChunk(id: string, start: number, body: Readable): Promise<number> {
        /* … */
    }
    private async download(id: string): Promise<Buffer> {
        /* … */
    }
    private async remove(id: string): Promise<void> {
        /* … */
    }
}
```

### Required Members

These are `abstract` on `BaseStorage`; the class doesn't compile without them:

- **`meta: MetaStorage<TFile>`** - where upload metadata is stored
- **`create(file: FileInit, options?): Promise<TFile>`** - start an upload / create a file
- **`write(part: FilePart | FileQuery | TFile, options?): Promise<TFile>`** - write bytes at `part.start`
- **`get(query: FileQuery, options?): Promise<FileReturn>`** - file metadata plus its `content` buffer
- **`delete(query: FileQuery, options?): Promise<TFile>`** - delete a file
- **`copy(name: string, destination: string, options?): Promise<TFile>`** - copy a file
- **`move(name: string, destination: string, options?): Promise<TFile>`** - move a file

### Overridable Members (have defaults)

- **`list(limit?, options?): Promise<TFile[]>`** - default throws `"Not implemented"`; override it to support listing (`Files.list`, REST/multipart `GET` collection)
- **`getStream(query, options?)`** - default calls `get()` and wraps the buffer; override for real streaming (and `range` support)
- **`exists(query, options?)`** - default checks the meta storage
- **`update(query, metadata)`** - default merges into the stored metadata
- **`getReadUrl(key, options?)` / `getUploadUrl(key, options?)`** - default rejects with `METHOD_NOT_ALLOWED`; back `Files.url()` / `Files.signedUploadUrl()`
- **`listDirectory(options)`** - default rejects with `METHOD_NOT_ALLOWED`; set `supportsDelimiter = true` when you implement it
- **`deleteBatch` / `copyBatch` / `moveBatch`** - default loops over the single-item methods
- **`normalizeError(error: Error): HttpError`** - default maps errors to a generic `HttpError`
- **`raw`** getter - your native client (default `undefined`)
- Capability flags: `supportsRange`, `supportsMetadata`, `supportsCacheControl`, `supportsDelimiter` (all `false` by default), and `checksumTypes`

`MemoryStorage` (`src/storage/memory/memory-storage.ts`) is the smallest complete implementation and a good reference.

### Using Instrumentation

The base class provides `instrumentOperation()` for automatic metrics collection:

```typescript
public async create(config: FileInit): Promise<File> {
    return this.instrumentOperation(
        "create",
        async () => {
            // Your implementation
            const file = await this.createFile(config);
            await this.meta.save(file.id, file);
            await this.onCreate(file);
            return file;
        },
        {
            custom_attribute: "value",
        },
    );
}
```

### Batch Operations

Batch operations are automatically implemented by the base class, but you can override them:

```typescript
// import type { BatchOperationResponse } from "@visulima/storage";
public override async deleteBatch(ids: string[]): Promise<BatchOperationResponse<File>> {
    // Custom batch delete implementation
    const results = await Promise.allSettled(
        ids.map((id) => this.delete({ id })),
    );

    const successful: File[] = [];
    const failed: Array<{ error: string; id: string }> = [];

    results.forEach((result, index) => {
        if (result.status === "fulfilled") {
            successful.push(result.value);
        } else {
            failed.push({
                id: ids[index],
                error: result.reason.message,
            });
        }
    });

    return {
        successful,
        failed,
        successfulCount: successful.length,
        failedCount: failed.length,
    };
}
```

## Creating Custom MetaStorage

Create custom metadata storage by extending `MetaStorage`:

```typescript
import { MetaStorage } from "@visulima/storage";
import type { File } from "@visulima/storage";

interface DatabaseMetaStorageOptions {
    connectionString: string;
    tableName?: string;
}

class DatabaseMetaStorage<T extends File = File> extends MetaStorage<T> {
    private readonly connectionString: string;
    private readonly tableName: string;

    public constructor(config: DatabaseMetaStorageOptions) {
        super({
            prefix: config.tableName ? `${config.tableName}_` : "",
            suffix: "",
        });

        this.connectionString = config.connectionString;
        this.tableName = config.tableName || "file_metadata";
    }

    public override async save(id: string, file: T): Promise<T> {
        // Save metadata to database
        await this.db.query(
            `INSERT INTO ${this.tableName} (id, metadata) VALUES ($1, $2) 
             ON CONFLICT (id) DO UPDATE SET metadata = $2`,
            [id, JSON.stringify(file)],
        );

        return file;
    }

    public override async get(id: string): Promise<T> {
        // Retrieve metadata from database
        const result = await this.db.query(`SELECT metadata FROM ${this.tableName} WHERE id = $1`, [id]);

        if (result.rows.length === 0) {
            throw new Error("File not found");
        }

        return JSON.parse(result.rows[0].metadata) as T;
    }

    public override async delete(id: string): Promise<void> {
        // Delete metadata from database
        await this.db.query(`DELETE FROM ${this.tableName} WHERE id = $1`, [id]);
    }

    public override async touch(id: string, file: T): Promise<T> {
        // Update last accessed timestamp
        await this.db.query(`UPDATE ${this.tableName} SET last_accessed = NOW() WHERE id = $1`, [id]);

        return file;
    }
}
```

### MetaStorage Methods

Implement these methods in your custom `MetaStorage`:

- **`save(id: string, file: T): Promise<T>`** - Save file metadata
- **`get(id: string): Promise<T>`** - Retrieve file metadata
- **`delete(id: string): Promise<void>`** - Delete file metadata
- **`touch(id: string, file: T): Promise<T>`** - Update last accessed timestamp

### Conditional Saves

Chunked REST uploads write the same record from several requests at once, possibly from several
server processes. To keep that record consistent across processes, a `MetaStorage` can support
an atomic compare-and-swap:

1. Set `supportsConditionalSave` to `true`.
2. In `get()`, attach the record's version (an ETag, a row version, a content hash) with `setMetaVersion(file, version)`.
3. Implement `saveIfVersion(id, file, version)`: save only while the stored record still has `version`, attach the new version, and return `undefined` when it changed or is gone.

```typescript
import { MetaStorage, setMetaVersion } from "@visulima/storage";

class DatabaseMetaStorage<T extends File = File> extends MetaStorage<T> {
    public override readonly supportsConditionalSave = true;

    public override async saveIfVersion(id: string, file: T, version: string): Promise<T | undefined> {
        const { rowCount, rows } = await this.db.query(
            `UPDATE ${this.tableName} SET data = $1, version = version + 1 WHERE id = $2 AND version = $3 RETURNING version`,
            [JSON.stringify(file), id, Number(version)],
        );

        if (rowCount === 0) {
            return undefined;
        }

        setMetaVersion(file, String(rows[0].version));

        return file;
    }
}
```

The bundled metadata storages (local, memory, S3, aws-light, GCS and Azure) all support this.
Without it, concurrent saves are only merged within one process.

### Using Custom MetaStorage

Use your custom `MetaStorage` with any storage backend:

```typescript
import { DiskStorage } from "@visulima/storage";
import { DatabaseMetaStorage } from "./database-meta-storage";

const metaStorage = new DatabaseMetaStorage({
    connectionString: process.env.DATABASE_URL,
    tableName: "file_metadata",

    directory: "./uploads",
    metaStorage, // Use custom metadata storage
});
```

## Complete Example: Redis Storage Backend

A Redis-backed adapter: bytes in Redis, upload metadata in a `MemoryMetaStorage` (swap in a shared meta storage for multi-process deployments).

```typescript
import { buffer } from "node:stream/consumers";

import type { FileInit, FilePart, FileQuery } from "@visulima/storage";
import { AbstractBaseStorage, ERRORS, File, MemoryMetaStorage, throwErrorCode } from "@visulima/storage";
import Redis from "ioredis";

type FileReturn = Awaited<ReturnType<AbstractBaseStorage["get"]>>;

interface RedisStorageOptions {
    redis: Redis;
    prefix?: string;
}

class RedisStorage extends AbstractBaseStorage<File> {
    public static override readonly name: string = "redis";

    protected meta = new MemoryMetaStorage<File>();

    private readonly redis: Redis;
    private readonly prefix: string;

    public constructor(config: RedisStorageOptions) {
        super({ maxUploadSize: "100MB", allowMIME: ["*/*"] });

        this.redis = config.redis;
        this.prefix = config.prefix ?? "visulima:";
    }

    public override get raw(): Redis {
        return this.redis;
    }

    public async create(init: FileInit): Promise<File> {
        return this.instrumentOperation("create", async () => {
            const file = new File(init);

            await this.validate(file);

            file.bytesWritten = 0;
            file.status = "created";

            await this.saveMeta(file);
            await this.onCreate(file);

            return file;
        });
    }

    public async write(part: FilePart | FileQuery | File): Promise<File> {
        return this.instrumentOperation("write", async () => {
            const file = await this.getMeta(part.id);

            if (!("body" in part) || !part.body) {
                return file;
            }

            const chunk = await buffer(part.body);

            // SETRANGE writes at the chunk's offset and grows the value as needed
            await this.redis.setrange(this.key(file.id), part.start, chunk);

            file.bytesWritten = await this.redis.strlen(this.key(file.id));
            file.status = file.bytesWritten === file.size ? "completed" : "part";

            await this.saveMeta(file);

            return file;
        });
    }

    public async get(query: FileQuery): Promise<FileReturn> {
        return this.instrumentOperation("get", async () => {
            const file = await this.getMeta(query.id);
            const content = await this.redis.getBuffer(this.key(file.id));

            if (!content) {
                return throwErrorCode(ERRORS.FILE_NOT_FOUND);
            }

            return { ...file, content, size: content.length } as FileReturn;
        });
    }

    public async delete(query: FileQuery): Promise<File> {
        return this.instrumentOperation("delete", async () => {
            const file = await this.getMeta(query.id);

            await this.redis.del(this.key(file.id));
            await this.deleteMeta(file.id);

            const deleted = { ...file, status: "deleted" } as File;

            await this.onDelete(deleted);

            return deleted;
        });
    }

    public async copy(source: string, destination: string): Promise<File> {
        return this.instrumentOperation("copy", async () => {
            const file = await this.getMeta(source);

            await this.redis.copy(this.key(source), this.key(destination), "REPLACE");

            const copied = { ...file, id: destination, name: destination } as File;

            await this.saveMeta(copied);

            return copied;
        });
    }

    public async move(source: string, destination: string): Promise<File> {
        const moved = await this.copy(source, destination);

        await this.delete({ id: source });

        return moved;
    }

    public override async list(limit = 100): Promise<File[]> {
        const keys = await this.redis.keys(`${this.prefix}file:*`);
        const ids = keys.slice(0, limit).map((key) => key.slice(`${this.prefix}file:`.length));

        return Promise.all(ids.map((id) => this.getMeta(id)));
    }

    private key(id: string): string {
        return `${this.prefix}file:${id}`;
    }
}

// Usage
const storage = new RedisStorage({
    redis: new Redis(process.env.REDIS_URL),
    prefix: "myapp:",
});
```

## Best Practices

1. **Implement Error Normalization** - Override `normalizeError()` to map your backend's errors to meaningful status codes
2. **Use Instrumentation** - Wrap operations with `instrumentOperation()` for automatic metrics
3. **Handle Metadata** - Properly save and retrieve metadata using the `meta` property
4. **Call Hooks** - Call lifecycle hooks (`onCreate`, `onUpdate`, `onDelete`) at appropriate times. Don't call `onComplete` from `write()`: the upload handlers call it once the upload completes
5. **Persist the Offset** - Save the file's metadata (including `bytesWritten`) after every successful `write()`. The TUS handler compares a chunk's `Upload-Offset` with the stored offset and reports it on `HEAD`
6. **List Only Verified Checksums** - Put an algorithm in `checksumTypes` only if `write()` really verifies `checksum` against the bytes; the TUS handler verifies the rest itself
7. **Handle Streams** - Properly handle Readable streams for file data
8. **Validate Inputs** - Validate file sizes, MIME types, and other constraints
9. **Handle Concurrency** - Use file locking for concurrent access (the base class provides protected `lock()` / `unlock()`)
10. **Support Batch Operations** - Implement batch operations for better performance
11. **Test Thoroughly** - Test all operations including error cases
12. **Document Your Storage** - Document any limitations or special behavior

## Integration with Handlers

Your custom storage backend works seamlessly with all handlers:

```typescript
import { Multipart } from "@visulima/storage/handler/http/fetch";
import Redis from "ioredis";

import { RedisStorage } from "./redis-storage";

const storage = new RedisStorage({
    redis: new Redis(process.env.REDIS_URL),
});

const multipart = new Multipart({ storage });

// Use with any framework
app.post("/upload", async (request) => {
    return await multipart.fetch(request);
});
```
