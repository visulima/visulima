# OpenAPI Documentation

Visulima Storage provides OpenAPI (Swagger) specifications for all upload handlers, allowing you to automatically generate API documentation for your file upload endpoints.

## Overview

The package exports four OpenAPI generators:

- **`xhrOpenApiSpec(origin, path, options?)`** - Multipart/form-data uploads
- **`tusOpenApiSpec(path, options?)`** - TUS resumable upload protocol
- **`restOpenApiSpec(origin, path, options?)`** - REST API for direct binary and chunked uploads
- **`transformOpenApiSpec(path?, tags?)`** - Media transformation query parameters on `GET <path>/{id}`

Each returns a complete OpenAPI 3.0.3 document (`openapi`, `info`, `paths`, `components`), so a single spec can be handed straight to Swagger UI. Override `info` (or add `servers`) by spreading the result.

## Installation

OpenAPI specs are included in the main package - no additional installation required.

```bash
npm install @visulima/storage
```

## Basic Usage

```typescript
import { restOpenApiSpec, transformOpenApiSpec, tusOpenApiSpec, xhrOpenApiSpec } from "@visulima/storage/openapi";

const spec = {
    ...xhrOpenApiSpec("http://localhost:3000", "/files"),
    info: { title: "My upload API", version: "1.0.0" },
    servers: [{ url: "http://localhost:3000" }],
};
```

## XHR OpenAPI Spec (Multipart Uploads)

```typescript
import { xhrOpenApiSpec } from "@visulima/storage/openapi";

const spec = xhrOpenApiSpec("http://localhost:3000", "/files", {
    transformer: "image",
    supportedTransformerFormat: ["jpeg", "png", "webp", "avif"],
    tags: ["File Upload", "Multipart"],
});
```

Documents `POST <path>` (200 with the stored file's metadata and a `Location: <path>/<id>.<ext>` header), `GET <path>/{id}`, `GET <path>/{id}/metadata`, `DELETE <path>/{id}`, and `GET <path>` (listing, only served with `allowList: true`).

### Options

```typescript
interface OpenApiSpecOptions {
    /** Media transformer whose query parameters GET <path>/{id} accepts: "image", "video", "audio", or true for all */
    transformer?: boolean | "image" | "video" | "audio";
    /** Output formats offered by the transformer */
    supportedTransformerFormat?: string[];
    /** OpenAPI tags for the operations */
    tags?: string[];
}
```

`options` is optional for `xhrOpenApiSpec`, `restOpenApiSpec` and `tusOpenApiSpec`.

## TUS OpenAPI Spec (Resumable Uploads)

```typescript
import { tusOpenApiSpec } from "@visulima/storage/openapi";

const spec = tusOpenApiSpec("/files-tus", { tags: ["TUS Upload"] });
```

Documents `OPTIONS`, `POST` (creation), `HEAD`, `PATCH`, `GET <path>/{id}` and `GET <path>/{id}/metadata` (both answer with the upload's metadata as JSON) and `DELETE`. TUS has no listing endpoint. `transformer` / `supportedTransformerFormat` are accepted but ignored, since TUS `GET` never returns file bytes.

## REST OpenAPI Spec (Direct Binary Uploads)

```typescript
import { restOpenApiSpec } from "@visulima/storage/openapi";

const spec = restOpenApiSpec("http://localhost:3000", "/files", {
    transformer: "image",
    supportedTransformerFormat: ["jpeg", "png", "webp"],
});
```

### Features Documented

- `POST` - Upload a file (201), or initialize a chunked upload (201 with `X-Upload-ID` and `X-Chunked-Upload: true`)
- `PUT` - Replace an upload created through the route (200) or create one under a new ID (201); 400 for IDs not matching `^[\w-]{1,255}$`, 409 when an object without upload metadata already exists under that key
- `PATCH` - Upload a chunk: 202 while incomplete, 200 with `X-Upload-Complete: true` for the completing chunk
- `GET` - Retrieve a file, or list files when the handler is created with `allowList: true` (off by default)
- `DELETE` - Delete a single file, or batch delete (204 / 207 / 404)
- `HEAD` - File metadata and chunked upload progress

## Transform OpenAPI Spec (Media Transformations)

```typescript
import { transformOpenApiSpec } from "@visulima/storage/openapi";

const spec = transformOpenApiSpec("/files", ["Transform"]);
```

Documents the transformation query parameters of `GET <path>/{id}` (the handler's `GET` route with a `mediaTransformer` configured). Both arguments are optional (`path` defaults to `/`, tags to `["Transform"]`).

## Combining Multiple Specs

Specs for different paths can be merged by spreading `paths` and `components`. When two specs describe the **same path** (e.g. `xhrOpenApiSpec(…, "/files")` and `transformOpenApiSpec("/files")`), a plain spread replaces the whole path item, so `DELETE /files/{id}` from the multipart spec would disappear. Merge path items per method instead:

```typescript
import type { OpenAPIV3 } from "openapi-types";

const mergeSpecs = (info: OpenAPIV3.InfoObject, ...specs: Partial<OpenAPIV3.Document>[]): OpenAPIV3.Document => {
    const paths: OpenAPIV3.PathsObject = {};
    const components: Record<string, Record<string, unknown>> = {};

    for (const spec of specs) {
        for (const [path, item] of Object.entries(spec.paths ?? {})) {
            // Later specs win per method; other methods on the same path are kept
            paths[path] = { ...paths[path], ...item };
        }

        for (const [section, entries] of Object.entries(spec.components ?? {})) {
            components[section] = { ...components[section], ...entries };
        }
    }

    return { components: components as OpenAPIV3.ComponentsObject, info, openapi: "3.0.3", paths };
};
```

### Express Example

```typescript
import express from "express";
import swaggerUi from "swagger-ui-express";
import { transformOpenApiSpec, xhrOpenApiSpec } from "@visulima/storage/openapi";

const app = express();

const spec = mergeSpecs(
    { title: "Visulima Storage API", version: "1.0.0" },
    xhrOpenApiSpec("http://localhost:3000", "/files", {
        transformer: "image",
        supportedTransformerFormat: ["jpeg", "png", "webp", "avif"],
    }),
    transformOpenApiSpec("/files", ["Transform"]),
);

app.use("/api-docs", swaggerUi.serve, swaggerUi.setup(spec));

app.listen(3000);
```

### Hono Example

```typescript
import { Hono } from "hono";
import { swaggerUI } from "@hono/swagger-ui";
import { tusOpenApiSpec, xhrOpenApiSpec } from "@visulima/storage/openapi";

const app = new Hono();

const spec = mergeSpecs(
    { title: "Visulima Storage API", description: "File upload API (Multipart & TUS)", version: "1.0.0" },
    xhrOpenApiSpec("http://localhost:3000", "/files"),
    tusOpenApiSpec("/files-tus"),
);

app.get("/openapi.json", (c) => c.json({ ...spec, servers: [{ url: "http://localhost:3000" }] }));
app.get("/", swaggerUI({ url: "/openapi.json" }));

export default app;
```

## Shared Components

The OpenAPI specs include shared components that can be reused:

```typescript
import { sharedErrorSchemaObject, sharedFileMetaExampleObject, sharedFileMetaSchemaObject, sharedGet, sharedGetList } from "@visulima/storage/openapi";
```

- **`sharedErrorSchemaObject`** - Standard error response schema
- **`sharedFileMetaExampleObject`** - Example file metadata
- **`sharedFileMetaSchemaObject`** - File metadata schema
- **`sharedGet(operationId, tags, transformer?, formats?)`** - Standard GET operation definition
- **`sharedGetList(operationId, tags)`** - Standard GET list operation definition (array, or `{ data, meta }` when paginated)

```typescript
import { sharedErrorSchemaObject, sharedFileMetaSchemaObject, sharedGet } from "@visulima/storage/openapi";

const customSpec = {
    openapi: "3.0.3",
    info: { title: "Custom API", version: "1.0.0" },
    paths: {
        "/custom-endpoint/{id}": {
            get: sharedGet("customGet", ["Custom"]),
        },
    },
    components: {
        schemas: {
            ...sharedErrorSchemaObject,
            ...sharedFileMetaSchemaObject,
        },
    },
};
```

## Complete Example

```typescript
import express from "express";
import swaggerUi from "swagger-ui-express";
import { restOpenApiSpec, transformOpenApiSpec, tusOpenApiSpec, xhrOpenApiSpec } from "@visulima/storage/openapi";

const app = express();
const PORT = process.env.PORT || 3000;
const BASE_URL = `http://localhost:${PORT}`;

const spec = mergeSpecs(
    { title: "Visulima Storage API", version: "1.0.0", description: "File upload and transformation API" },
    xhrOpenApiSpec(BASE_URL, "/files", {
        transformer: "image",
        supportedTransformerFormat: ["jpeg", "png", "webp", "avif"],
        tags: ["Multipart Upload"],
    }),
    tusOpenApiSpec("/files-tus", { tags: ["TUS Upload"] }),
    restOpenApiSpec(BASE_URL, "/files-rest", { tags: ["REST Upload"] }),
    transformOpenApiSpec("/files", ["Transform"]),
);

app.use("/api-docs", swaggerUi.serve, swaggerUi.setup({ ...spec, servers: [{ url: BASE_URL, description: "Development server" }] }));

app.listen(PORT, () => {
    console.log(`API docs available at ${BASE_URL}/api-docs`);
});
```

## Best Practices

1. **Merge per method** - Use a per-path merge like `mergeSpecs` above when two specs share a path
2. **Use Consistent Tags** - Organize endpoints with meaningful tags
3. **Document Transformers** - Pass `transformer` to the multipart/REST specs when a `mediaTransformer` is configured
4. **Set `info` and `servers`** - The defaults are generic; spread your own over the result
5. **Serve from Production URLs** - Use your public origin for `origin` and `servers`
