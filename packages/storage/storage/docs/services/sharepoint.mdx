# SharePoint

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage.

## Overview

A SharePoint document library is a Microsoft Graph drive. The adapter resolves a site and document library to a `driveId`, then delegates every operation to an internal [`OneDriveStorage`](./onedrive.mdx). Auth, read/upload URLs and limits are the same as OneDrive's. Site resolution runs lazily on the first storage operation.

## Usage

```ts
import { SharePointStorage } from "@visulima/storage/provider/sharepoint";

const storage = new SharePointStorage({
    siteUrl: "https://contoso.sharepoint.com/sites/Marketing",
    documentLibrary: "Documents",
    clientCredentials: {
        tenantId: process.env.SHAREPOINT_TENANT_ID!,
        clientId: process.env.SHAREPOINT_CLIENT_ID!,
        clientSecret: process.env.SHAREPOINT_CLIENT_SECRET!,
    },
});
```

## Site targeting

Resolved in this order:

1. `driveId` (env `SHAREPOINT_DRIVE_ID`) — skips site resolution.
2. `siteId` (env `SHAREPOINT_SITE_ID`).
3. `siteUrl` (env `SHAREPOINT_SITE_URL`) — parsed into host name and path.
4. `hostname` (env `SHAREPOINT_HOSTNAME`) + `sitePath` (e.g. `/sites/Marketing`).

`documentLibrary` picks a library of the resolved site by display name; without it the site's default drive is used.

## Configuration

| Option                                                   | Description                                                                                           |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `clientCredentials` / `oauth` / `accessToken` / `client` | Auth, same shapes as [OneDrive](./onedrive.mdx). Env fallbacks read `SHAREPOINT_*`, then `ONEDRIVE_*` |
| `driveId`, `siteId`, `siteUrl`, `hostname`, `sitePath`   | Site / library targeting (see above)                                                                  |
| `documentLibrary`                                        | Library display name within the site                                                                  |
| `rootFolderPath`                                         | Folder inside the library that acts as the bucket root; must already exist                            |
| `publicByDefault`                                        | `getReadUrl` mints an anonymous view link                                                             |
| `copyTimeoutMs`                                          | Timeout for Graph's async-copy monitor (default `60000`)                                              |
| `metaStorageConfig`                                      | Where upload metadata is kept (default: local temp directory)                                         |

## Limitations

- Uploads are single-shot through the adapter, so resumable/chunked uploads (TUS, chunked REST) must send the whole file in one request. Use `getUploadUrl()` (a Graph upload session) for large direct-from-client transfers.
- Per-operation `signal` / `timeout` are best-effort: the SDK can't cancel an in-flight request. `retries` is honoured.
