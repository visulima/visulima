# Microsoft OneDrive

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage, OAuth wiring, and Graph-specific behavior.

## Overview

The OneDrive adapter targets Microsoft Graph (`/me/drive` or `/users/{id}/drive`) via the official `@microsoft/microsoft-graph-client`. It supports app-only (client-credentials) auth for service deployments, refresh-token auth for end-user flows, or a pre-built Graph client. Refresh-token caching uses a shared OAuth helper with 60 s leeway.

## Installation

```sh
npm install @microsoft/microsoft-graph-client
```

```sh
yarn add @microsoft/microsoft-graph-client
```

```sh
pnpm add @microsoft/microsoft-graph-client
```

## Usage

Pick exactly one auth shape: `clientCredentials`, `oauth`, `accessToken` or a pre-built `client`.

### App-only (client-credentials)

```ts
import { OneDriveStorage } from "@visulima/storage/provider/onedrive";

const storage = new OneDriveStorage({
    clientCredentials: {
        clientId: process.env.ONEDRIVE_CLIENT_ID!,
        clientSecret: process.env.ONEDRIVE_CLIENT_SECRET!,
        tenantId: process.env.ONEDRIVE_TENANT_ID!,
    },
    userId: process.env.ONEDRIVE_USER_ID!, // app-only tokens can't use /me/drive: set userId, driveId or siteId
    rootFolderPath: "uploads",
});
```

### Refresh-token (delegated end-user auth)

```ts
const storage = new OneDriveStorage({
    oauth: {
        clientId: process.env.ONEDRIVE_CLIENT_ID!,
        clientSecret: process.env.ONEDRIVE_CLIENT_SECRET,
        tenantId: process.env.ONEDRIVE_TENANT_ID, // optional; defaults to `common`
        refreshToken: process.env.ONEDRIVE_REFRESH_TOKEN!,
    },
});
```

### Static or dynamic access token

```ts
const storage = new OneDriveStorage({
    accessToken: async () => getTokenFromYourIdentityLayer(),
});
```

### Pre-built client

```ts
import { Client } from "@microsoft/microsoft-graph-client";

const storage = new OneDriveStorage({
    client: Client.init({ authProvider: async (done) => done(null, await getToken()) }),
});
```

Pre-built clients bypass the adapter's auth bookkeeping entirely.

## Configuration

| Option              | Type                                                   | Description                                                                       |
| ------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------- |
| `clientCredentials` | `{ clientId, clientSecret, tenantId }`                 | App-only auth                                                                     |
| `oauth`             | `{ clientId, clientSecret?, refreshToken, tenantId? }` | Delegated auth with a refresh token                                               |
| `accessToken`       | `string \| () => string \| Promise<string>`            | Static token, or a function returning a fresh one per call                        |
| `client`            | `Client`                                               | Pre-built Graph client                                                            |
| `driveId`           | `string`                                               | Target `/drives/{id}`                                                             |
| `siteId`            | `string`                                               | Target a SharePoint site's default drive (`/sites/{id}/drive`)                    |
| `userId`            | `string`                                               | Target `/users/{id}/drive`                                                        |
| `rootFolderPath`    | `string`                                               | Folder inside the drive that acts as the bucket root; must already exist          |
| `publicByDefault`   | `boolean`                                              | `getReadUrl` mints an anonymous view link instead of the short-lived download URL |
| `copyTimeoutMs`     | `number`                                               | Timeout for polling Graph's async-copy monitor (default `60000`)                  |
| `metaStorageConfig` | `LocalMetaStorageOptions`                              | Where upload metadata is kept (default: local temp directory)                     |

### `rootFolderPath`

All operations are rooted under `rootFolderPath` so the same drive can host multiple logical "buckets":

```ts
new OneDriveStorage({
    /* …auth… */
    rootFolderPath: "uploads/avatars",
});
```

Keys are then joined as `uploads/avatars/<key>` inside the drive root. The folder must already exist.

### Drive selection

`driveId`, `siteId` and `userId` are mutually exclusive:

- None set: `/me/drive` (the signed-in user; delegated auth only).
- `driveId`: `/drives/{id}`.
- `siteId`: `/sites/{id}/drive`.
- `userId`: `/users/{id}/drive`. Required (or `driveId` / `siteId`) for `clientCredentials`, since Graph rejects `/me/drive` for app-only tokens.

## URL Generation

### `getReadUrl(key, options?)`

- Default: returns the `@microsoft.graph.downloadUrl` from the item metadata (pre-authenticated, short-lived, ~1 h).
- `publicByDefault: true`: calls `createLink` (`type: "view", scope: "anonymous"`) to mint an anonymous sharing link.
- `responseContentDisposition` is not supported.

### `getUploadUrl(key, options?)`

Returns an upload-session URL from `POST /drive/root:/{path}:/createUploadSession`. The caller drives the session with `PUT` requests carrying `Content-Range` headers — see Microsoft's [resumable upload docs](https://learn.microsoft.com/en-us/graph/api/driveitem-createuploadsession).

## Features

- **Two server-side auth flows** — client-credentials for app deployments, refresh-token for delegated end-user access.
- **Shared OAuth helper** — refresh-token mode reuses the same caching/leeway logic as the Dropbox adapter.
- **Upload sessions** — `getUploadUrl()` initiates a Microsoft Graph resumable upload session.
- **Sharing-link minting** — `publicByDefault` swaps the read-URL strategy without changing the call site.

## Limitations

- Single-shot writes via `write()` buffer the part stream — use `getUploadUrl()` for large transfers.
- `parentReference.path` requires the literal `/drive/root:` prefix; the adapter handles this for you but `storage.raw` callers should be aware.
- Read URLs (`@microsoft.graph.downloadUrl`) are short-lived (~1 h) — re-call `getReadUrl()` for each request rather than caching.
