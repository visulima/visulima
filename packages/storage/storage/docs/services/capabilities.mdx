# Adapter Capabilities

Different storage backends expose different primitives. This page enumerates which features each adapter implements natively, simulates, or rejects — so you can choose the right adapter for your use case without reading source.

Legend:

- ✅ **native** — the underlying SDK / API provides this directly
- 🟡 **partial** — supported with caveats (documented in the adapter's page)
- ❌ **not supported** — the adapter throws `METHOD_NOT_ALLOWED` or `STORAGE_ERROR`
- 🔁 **simulated** — implemented via `download` + reupload or similar fallback

## Uploads, reads & listing

From the adapter flags `supportsResumableWrites`, `sequentialWrites`, `supportsRange` and `supportsDelimiter` (also exposed as `files.capabilities`).

| Adapter        | Chunked / resumable writes   | Ranged reads | Native `delimiter` listing | Upload metadata by default |
| -------------- | ---------------------------- | ------------ | -------------------------- | -------------------------- |
| S3 / R2 / etc. | 🟡 sequential, ≥ 5 MiB parts | ✅           | ✅                         | bucket (`<id>.META`)       |
| S3 (light)     | 🟡 sequential, ≥ 5 MiB parts | ✅           | ✅                         | bucket (`<id>.META`)       |
| Azure Blob     | 🟡 sequential                | ❌           | 🔁                         | container                  |
| GCS            | 🟡 sequential                | ❌           | ✅                         | bucket                     |
| Local (disk)   | ✅ any offset                | ✅           | 🔁                         | upload directory           |
| Memory         | ✅ any offset                | ✅           | 🔁                         | in-process                 |
| FTP / SFTP     | ❌ single request            | ✅           | 🔁                         | local disk                 |
| All others     | ❌ single request            | ❌           | 🔁                         | local disk                 |

"Single request" adapters store each object in one call: the TUS handler rejects partial chunks, so clients must send the whole file per request. "Local disk" metadata defaults to the OS temp directory — see [Upload metadata](./index.mdx#upload-metadata) before running several instances.

## Read & write URLs

`Files.url()` calls `getReadUrl()` and `Files.signedUploadUrl()` calls `getUploadUrl()`. Adapters that don't implement a method inherit the `BaseStorage` default, which rejects with `METHOD_NOT_ALLOWED`.

| Adapter        | `getReadUrl()`                                                   | `getUploadUrl()`                       |
| -------------- | ---------------------------------------------------------------- | -------------------------------------- |
| S3 / R2 / etc. | ✅ presigned `GET`                                               | ✅ presigned `PUT`                     |
| S3 (light)     | ❌                                                               | ❌                                     |
| Bun S3         | ✅ `presign` (`GET`)                                             | ✅ `presign` (`PUT`)                   |
| Azure Blob     | ✅ SAS                                                           | ✅ SAS (`cw` permissions)              |
| GCS            | ❌                                                               | ❌ (resumable URLs handled internally) |
| Firebase       | ✅ V2 signed URL, or `publicBaseUrl`                             | ✅ V2 signed `PUT`                     |
| Vercel Blob    | ❌                                                               | ❌ (use Vercel client tokens)          |
| Netlify Blobs  | ❌                                                               | ❌                                     |
| Local (disk)   | ❌                                                               | ❌                                     |
| FTP / SFTP     | ❌                                                               | ❌                                     |
| Dropbox        | ✅ temporary link (≤ 4 h) or public shared link                  | ❌                                     |
| Google Drive   | 🟡 only when `publicByDefault: true`                             | ✅ resumable session URL               |
| OneDrive       | ✅ `@microsoft.graph.downloadUrl` or `createLink`                | ✅ `createUploadSession`               |
| SharePoint     | ✅ same as OneDrive                                              | ✅ same as OneDrive                    |
| Box            | ✅ short-lived download URL (shared link with `publicByDefault`) | ❌                                     |
| Supabase       | ✅ `createSignedUrl` (≤ 7 d)                                     | ✅ `createSignedUploadUrl`             |
| UploadThing    | ✅ CDN URL (public ACL) or `generateSignedURL` (private)         | ❌                                     |
| Bunny Storage  | 🟡 only with `publicBaseUrl` (Pull Zone)                         | ❌                                     |
| Cloudinary     | ✅ delivery URL, or `private_download_url` for non-public types  | ❌                                     |
| PocketBase     | ✅ file URL (`publicBaseUrl` or a fresh file token)              | ❌                                     |
| Memory         | 🟡 synthetic `memory://${key}`                                   | 🟡 synthetic `memory://${key}`         |
| WebDAV         | ❌                                                               | ❌                                     |

| Cloudinary     | n/a             | ❌ — rejected with `BAD_REQUEST`                                            |

| -------------- | ---------------------- | --------------------------------------- | ------------------------------------- |
| S3 / R2 / etc. | ✅ CopyObject          | 🔁 copy + delete                        | ✅ `Prefix`                           |
| Azure Blob     | ✅ Copy Blob           | 🔁 copy + delete                        | 🟡 configured `root` only             |
| GCS            | ✅ copy                | 🔁 copy + delete                        | ✅ `prefix`                           |
| Vercel Blob    | ✅ copy                | 🔁 copy + delete                        | 🟡 facade-side filter                 |
| Netlify Blobs  | 🔁 download + reupload | 🔁 copy + delete                        | ✅ `prefix`                           |
| Local (disk)   | ✅ fs.copyFile         | ✅ fs.rename (copy + delete on `EXDEV`) | ✅ recursive scan                     |
| Dropbox        | ✅ filesCopyV2         | ✅ filesMoveV2                          | 🟡 recursive listing of root          |
| Google Drive   | ✅ files.copy          | 🔁 copy + delete                        | 🟡 virtual-key + appProperties        |
| OneDrive       | ✅ async copy          | ✅ patch parent                         | 🟡 recursive walk, client-side        |
| SharePoint     | ✅ same as OneDrive    | ✅ same as OneDrive                     | 🟡 same as OneDrive                   |
| Box            | ✅ copyFile            | ✅ updateFile parent                    | 🟡 folder root, cached IDs            |
| Supabase       | ✅ bucket.copy         | ✅ bucket.move                          | 🟡 recursive walk, paged              |
| UploadThing    | 🔁 download + reupload | 🔁 copy + delete                        | 🟡 client-side prefix filter          |
| Bunny Storage  | 🔁 download + reupload | 🔁 copy + delete                        | 🟡 recursive walk, client-side        |
| Firebase       | ✅ GCS copy            | ✅ GCS move                             | ✅ `prefix`                           |
| Cloudinary     | ✅ upload from URL     | ✅ `uploader.rename`                    | 🟡 all assets of the configured types |
| PocketBase     | 🔁 download + reupload | 🔁 copy + delete                        | 🟡 client-side                        |
| FTP / SFTP     | 🔁 download + reupload | ✅ rename (copy + delete fallback)      | 🟡 recursive walk, client-side        |
| Memory         | ✅ Map clone           | ✅ copy + delete                        | ✅ in-memory prefix scan              |
| WebDAV         | ✅ `COPY`              | ✅ `MOVE`                               | 🟡 `Depth: 1` walk of root            |

## Auth model

| Adapter        | Auth shapes                                                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| S3 / R2 / etc. | static / SSO / EC2 / env (AWS SDK credential chain)                                                                                                    |
| Azure Blob     | connection string, account key, SAS token, AAD                                                                                                         |
| GCS            | service-account JSON, ADC, key file, OAuth                                                                                                             |
| Vercel Blob    | OIDC (`VERCEL_OIDC_TOKEN` + `BLOB_STORE_ID`, recommended on Vercel), `BLOB_READ_WRITE_TOKEN`                                                           |
| Netlify Blobs  | env-injected on Netlify, explicit token otherwise                                                                                                      |
| Local (disk)   | filesystem permissions                                                                                                                                 |
| Dropbox        | access token, refresh token + app key (+ secret), pre-built `Dropbox`                                                                                  |
| Google Drive   | service-account JSON, key file, OAuth (refresh token), JWT, env (`GOOGLE_DRIVE_CLIENT_EMAIL` + `GOOGLE_DRIVE_PRIVATE_KEY`, or `GOOGLE_DRIVE_KEY_FILE`) |
| OneDrive       | static access token, client-credentials (app-only), refresh token + redirect, pre-built Graph client                                                   |
| Box            | developer token, OAuth, CCG (enterprise / user), JWT, env                                                                                              |
| Supabase       | service-role key (env or explicit), pre-built `StorageClient`                                                                                          |
| UploadThing    | dashboard token (base64 JSON with `apiKey` + `appId`)                                                                                                  |
| Bunny Storage  | zone + access key + region (env or explicit), pre-built `StorageZone`                                                                                  |
| Firebase       | an initialized `firebase-admin` bucket (its service account)                                                                                           |
| SharePoint     | same as OneDrive (env `SHAREPOINT_*` / `ONEDRIVE_*`)                                                                                                   |
| Cloudinary     | `CLOUDINARY_URL`, or cloud name + API key + secret (env or explicit)                                                                                   |
| PocketBase     | superuser email + password (env `POCKETBASE_ADMIN_*`), auth token, pre-built client                                                                    |
| FTP / SFTP     | connection options (password, key)                                                                                                                     |
| Memory         | none (in-process only)                                                                                                                                 |
| WebDAV         | HTTP Basic (`username` + `password`), Bearer `token`, custom `headers`                                                                                 |

## Error normalization

All consumer adapters propagate adapter-native errors today, but the package ships `wrapStorageError` (in `@visulima/storage` → `utils/errors`) to normalize them into a canonical `UploadError` with a stable `ERRORS` code. Wired into HTTP-fetch throws on Google Drive (resumable session) and OneDrive (copy, createUploadSession, monitor, upload-session chunks).

Mapping rule of thumb:

| HTTP status | `ERRORS` code              |
| ----------- | -------------------------- |
| 400         | `BAD_REQUEST`              |
| 401 / 403   | `FORBIDDEN`                |
| 404         | `FILE_NOT_FOUND`           |
| 405         | `METHOD_NOT_ALLOWED`       |
| 409         | `FILE_CONFLICT`            |
| 410         | `GONE`                     |
| 413         | `REQUEST_ENTITY_TOO_LARGE` |
| 415         | `UNSUPPORTED_MEDIA_TYPE`   |
| 422         | `UNPROCESSABLE_ENTITY`     |
| 423         | `FILE_LOCKED`              |
| 429         | `TOO_MANY_REQUESTS`        |
| 503         | `STORAGE_BUSY`             |
| other 5xx   | `STORAGE_ERROR`            |
| other 4xx   | `BAD_REQUEST`              |

The native error is preserved on `UploadError.detail` for callers that need provider-specific shapes.

## When in doubt

Drop down to the native client via `storage.raw` — every adapter exposes the underlying SDK instance there, so you can bypass the unified contract when a feature isn't in the table above.
