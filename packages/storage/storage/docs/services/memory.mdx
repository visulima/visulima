# In-Memory Storage

> **Just need a quick in-memory store for tests?** Wrap `MemoryStorage` in the [`Files` facade](../files-facade.mdx) for a one-liner API. The adapter implements the full `BaseStorage` surface, so any framework that takes a `BaseStorage` works with it unchanged.

## Overview

`MemoryStorage` is a `BaseStorage` adapter backed by a `Map` inside the process. Nothing is persisted: everything lives in the Node.js heap until the process exits. It implements the full surface (`create`, `write`, `get`, `getStream`, `exists`, `delete`, `copy`, `move`, `list`, `getReadUrl`, `getUploadUrl`), supports ranged reads, and accepts chunked or resumable writes at any offset.

**Use it only for tests and single-process tools.** It is not a production store. Data is lost on restart, never evicted, and invisible to other processes or workers.

Good uses:

- **Unit and integration tests:** no temp directories, no cleanup, deterministic state.
- **Ephemeral environments:** smoke tests, preview builds, scripts.
- **Reference implementation:** the smallest adapter to read when you write your own.

## Installation

No extra dependencies. The adapter ships with `@visulima/storage`.

```ts
import { MemoryMetaStorage, MemoryStorage } from "@visulima/storage";
// also available from "@visulima/storage/provider/memory" (default export: MemoryStorage)
```

## Provider setup

None. There is no service, credential or CORS configuration.

## Configuration

```ts
import { MemoryStorage } from "@visulima/storage";

// Minimal
const storage = new MemoryStorage();
```

```ts
import { MemoryStorage } from "@visulima/storage";

// Test fixture with seed data and the same limits as production
const storage = new MemoryStorage({
    initial: { "users/1.json": '{"id":1}' },
    maxUploadSize: "10MB",
    allowMIME: ["application/json"],
});
```

| Option              | Type                                             | Default                 | Description                                                                                                                       |
| ------------------- | ------------------------------------------------ | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `initial`           | `Record<string, Buffer \| Uint8Array \| string>` | —                       | Seeds the store with `key → bytes` entries. Strings are UTF-8 encoded. Each entry gets a completed metadata record with id = key. |
| `metaStorageConfig` | `MetaStorageOptions`                             | `{}`                    | `prefix` / `suffix` / `logger` for the default `MemoryMetaStorage`.                                                               |
| `metaStorage`       | `MetaStorage`                                    | new `MemoryMetaStorage` | Share one metadata store between instances.                                                                                       |

All other `BaseStorageOptions` (`maxUploadSize`, `allowMIME`, `filename`, `validation`, `expiration`, hooks, `logger`, `metrics`, …) work as they do on the other adapters. That lets you test validation and lifecycle hooks with exactly the production settings. `retryConfig` and `defaultTimeout` have no effect. The adapter reads no environment variables.

## Metadata storage

Records live in a `MemoryMetaStorage` (another `Map`) in the same process. They are copied on every read and write, so callers never mutate the store by accident. Finished uploads keep their record. `delete()` removes it, and `purge()` only expires uploads that have a record.

## Behaviour & limits

| Aspect                     | Behaviour                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Chunked / resumable writes | ✅ Writes at any offset; out-of-order chunks don't overwrite each other. A `PUT` from byte 0 to a completed upload replaces it. |
| Checksums                  | None advertised (`checksumTypes: []`).                                                                                          |
| Range reads                | ✅ `supportsRange: true`. An invalid range on `get()` → `BAD_REQUEST`.                                                          |
| URLs                       | `getReadUrl(key)` / `getUploadUrl(key)` return a synthetic `memory://${key}`. Nothing listens on that scheme.                   |
| `list()`                   | Every stored entry, with size, content type and timestamps. `limit` is ignored.                                                 |
| `copy()` / `move()`        | Buffer copy. Move is copy followed by delete.                                                                                   |
| Isolation                  | Per instance. Two `MemoryStorage` objects never see each other's bytes, even when they share a `metaStorage`.                   |

## Seed the store

```ts
import { Files, MemoryStorage } from "@visulima/storage";

const adapter = new MemoryStorage({
    initial: {
        "users/1.json": '{"id":1}',
        "users/2.json": Buffer.from([0x01, 0x02, 0x03]),
    },
});

const files = new Files({ adapter });

await files.head("users/1.json"); // FileObject for the seeded entry
```

## Inspecting and resetting

`raw` returns the `Map` that holds the bytes:

```ts
import { Files, MemoryStorage } from "@visulima/storage";

const adapter = new MemoryStorage();
const files = new Files({ adapter });

await files.upload("k.txt", "x");

expect(adapter.raw.size).toBe(1);
expect(adapter.raw.has("k.txt")).toBe(true);

adapter.raw.clear(); // clears the bytes
adapter.meta.clear(); // clears the upload records too
```

## Sharing metadata between instances

```ts
import { MemoryMetaStorage, MemoryStorage } from "@visulima/storage";

const meta = new MemoryMetaStorage();
const a = new MemoryStorage({ metaStorage: meta });
const b = new MemoryStorage({ metaStorage: meta });
```

This is rarely needed. It helps when testing flows that only touch metadata.

## Using it with the handlers

```ts
// Node: e.g. supertest against an Express app
import express from "express";
import { MemoryStorage } from "@visulima/storage";
import { Tus } from "@visulima/storage/handler/http/node";

const storage = new MemoryStorage();
const app = express();

app.use("/upload/tus", new Tus({ storage }).handle);
```

```ts
// Fetch: call the handler directly in a test
import { MemoryStorage } from "@visulima/storage";
import { Rest } from "@visulima/storage/handler/http/fetch";

const rest = new Rest({ storage: new MemoryStorage() });

const response = await rest.fetch(new Request("http://localhost/files", { method: "POST", body: "hello", headers: { "content-type": "text/plain" } }));
```

## Caveats

- **Process-local:** the store disappears when the process exits. Use `DiskStorage` if data must survive between runs.
- **Unbounded growth:** there is no eviction. Clear `raw` and `meta` between test cases.
- **Single process:** workers, cluster forks and serverless invocations each get their own empty store. Use `DiskStorage` on a shared volume, or a real provider, for multi-process tests.

## Troubleshooting

| Symptom                                      | Cause / fix                                                                                                 |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `FILE_NOT_FOUND` in a second request or test | A different `MemoryStorage` instance (or process) handled it. Share one instance across the app under test. |
| State leaks between tests                    | Call `adapter.raw.clear()` and `adapter.meta.clear()` in `beforeEach`, or create a new instance per test.   |
| Heap grows during a long run                 | Nothing is evicted. Set `expiration` with `purgeInterval`, or clear the store yourself.                     |
