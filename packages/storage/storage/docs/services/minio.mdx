# MinIO

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage — pick that path when you're hosting an upload server.

## Overview

MinIO is a self-hostable, S3-compatible object store. There is no dedicated MinIO adapter: use [`S3Storage`](./amazon-s3.mdx) (Node.js) or [`AwsLightStorage`](./aws-light.mdx) (edge runtimes) with your MinIO endpoint. The `minio()` helper sets the endpoint, credentials and `forcePathStyle: true`, which MinIO needs unless you configured virtual-host-style domains.

## Installation

```sh
# S3Storage (Node.js)
pnpm add @visulima/storage @aws-sdk/client-s3 @aws-sdk/credential-providers @aws-sdk/s3-request-presigner

# or AwsLightStorage (edge)
pnpm add @visulima/storage aws4fetch
```

## Provider setup

1. **Create a bucket** — `mc mb myminio/uploads` (or the MinIO Console).
2. **Create a user or access key** — don't use the root credentials in production. Create a policy with the minimum actions and attach it to a user (`mc admin user add`) or a service account / access key:

    ```json
    {
        "Version": "2012-10-17",
        "Statement": [
            {
                "Effect": "Allow",
                "Action": ["s3:ListBucket", "s3:ListBucketMultipartUploads"],
                "Resource": ["arn:aws:s3:::uploads"]
            },
            {
                "Effect": "Allow",
                "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject", "s3:AbortMultipartUpload", "s3:ListMultipartUploadParts"],
                "Resource": ["arn:aws:s3:::uploads/*"]
            }
        ]
    }
    ```

    ```sh
    mc admin policy create myminio visulima-uploads policy.json
    mc admin policy attach myminio visulima-uploads --user uploader
    ```

    `s3:ListBucket` is required: without it a missing key answers `403` instead of `404`, which breaks metadata lookups and the startup bucket check.

3. **CORS** — only needed when a browser calls MinIO directly (presigned URLs, `clientDirectUpload`). MinIO configures CORS server-wide through `MINIO_API_CORS_ALLOW_ORIGIN` (default `*`); set it to your app's origin.
4. **Stale multipart uploads** — MinIO removes unfinished multipart uploads on its own after `MINIO_API_STALE_UPLOADS_EXPIRY` (default `24h`). `purge()` only aborts uploads this storage started.

## Configuration

### `minio()` helper

`import { minio } from "@visulima/storage/provider/aws/s3/clients"` returns an `S3ClientConfig` (`credentials`, `endpoint`, `region`, `forcePathStyle: true`). Every parameter falls back to environment variables:

| Parameter         | Type     | Required | Env fallback (in order)                                                |
| ----------------- | -------- | -------- | ---------------------------------------------------------------------- |
| `endpoint`        | `string` | yes      | `MINIO_ENDPOINT`, `AWS_ENDPOINT`                                       |
| `region`          | `string` | yes      | `MINIO_REGION`, `AWS_REGION`                                           |
| `accessKeyId`     | `string` | yes      | `MINIO_ACCESS_KEY_ID`, `MINIO_ACCESS_KEY`, `AWS_ACCESS_KEY_ID`         |
| `secretAccessKey` | `string` | yes      | `MINIO_SECRET_ACCESS_KEY`, `MINIO_SECRET_KEY`, `AWS_SECRET_ACCESS_KEY` |

`region` must match the server's configured region (`MINIO_SITE_REGION`, default `us-east-1`) or requests fail signature checks. All other options are the [`S3Storage` options](./amazon-s3.mdx#configuration).

### Minimal (local development)

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { minio } from "@visulima/storage/provider/aws/s3/clients";

const storage = new S3Storage({
    bucket: "uploads",
    ...minio({ endpoint: "http://localhost:9000", region: "us-east-1", accessKeyId: "minioadmin", secretAccessKey: "minioadmin" }),
});
```

### Production

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { minio } from "@visulima/storage/provider/aws/s3/clients";

const storage = new S3Storage({
    ...minio({
        endpoint: "https://minio.internal.example.com",
        region: "us-east-1",
        accessKeyId: process.env.MINIO_ACCESS_KEY_ID!,
        secretAccessKey: process.env.MINIO_SECRET_ACCESS_KEY!,
    }),
    bucket: "uploads",
    maxUploadSize: "10GB",
    expiration: { maxAge: "24h", purgeInterval: "1h" },
    logger: console,
});
```

### Edge (`AwsLightStorage`)

```ts
import { AwsLightStorage } from "@visulima/storage/provider/aws-light";

const storage = new AwsLightStorage({
    bucket: "uploads",
    region: "us-east-1",
    endpoint: "https://minio.example.com", // used path-style: <endpoint>/<bucket>/<key>
    accessKeyId: process.env.MINIO_ACCESS_KEY_ID!,
    secretAccessKey: process.env.MINIO_SECRET_ACCESS_KEY!,
});
```

## Metadata storage

Same as [Amazon S3](./amazon-s3.mdx#metadata-storage): each upload's record is a zero-byte `<id>.META` object in the bucket (JSON in the user-metadata header), skipped by `list()` and `purge()` and kept after the upload finishes. Every instance pointing at the same bucket shares it. Use `metaStorageConfig: { bucket }` for a separate bucket, or `metaStorageConfig: { directory }` for local disk (single instance only).

## Behaviour & limits

See [Amazon S3](./amazon-s3.mdx#behaviour--limits): sequential writes with parts of at least 5 MiB (except the last), range reads, native `delimiter` listing, presigned `GET`/`PUT` with `S3Storage`, and a `purge()` that only touches uploads this storage created.

## Using it with the handlers

```ts
// Node (Express)
import express from "express";
import { Tus } from "@visulima/storage/handler/http/node";

const app = express();

app.use("/files", new Tus({ storage }).handle);
```

```ts
// Fetch (Bun, Deno, Hono, …)
import { Rest } from "@visulima/storage/handler/http/fetch";

const rest = new Rest({ storage });

export default { fetch: (request: Request) => rest.fetch(request) };
```

```ts
// Files facade
import { Files } from "@visulima/storage";

const files = new Files({ adapter: storage });

await files.upload("reports/q1.pdf", buffer, { contentType: "application/pdf" });
```

## Troubleshooting

| Symptom                                       | Cause / fix                                                                                         |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `403` on reads of missing keys / not ready    | The policy lacks `s3:ListBucket` on the bucket ARN.                                                 |
| `SignatureDoesNotMatch`                       | `region` doesn't match the server region, or a proxy rewrites the `Host` header.                    |
| `NoSuchBucket` / DNS errors for `bucket.host` | Virtual-host addressing without a matching domain. Use the helper (it sets `forcePathStyle: true`). |
| Browser CORS errors                           | Set `MINIO_API_CORS_ALLOW_ORIGIN` to your origin.                                                   |
| `400` "chunks of at least 5 MiB" / `409`      | Use a client chunk size ≥ 5 MiB and resume from the offset `HEAD` returns.                          |
