# Bunny Storage

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage and Bunny-specific limitations (no presigned PUT, no signed-read URL).

## Overview

The Bunny Storage adapter wraps `@bunny.net/storage-sdk`. Writes go through the Storage API, authenticated with the zone's `AccessKey`. Server-side reads use `file.get(...).data()`. Public read URLs need a Pull Zone (or another CDN hostname) configured as `publicBaseUrl`.

Bunny Storage has no presigned upload URLs and no signed read URLs. The adapter writes on the server and builds public URLs from your CDN hostname.

## Installation

```sh
npm install @bunny.net/storage-sdk
```

```sh

```


## Provider setup

1. In the bunny.net dashboard, create a **Storage Zone** and pick its **main storage region**. It must match the adapter's `region`.
2. Open the zone's **FTP & API Access** page and copy the **password**. This is the `accessKey` the Storage API expects. The read-only password can't write, so use the full one.
3. Optional: to hand out read URLs, create a **Pull Zone** with the Storage Zone as its origin, and pass its hostname (or your custom domain) as `publicBaseUrl`. Files in a Pull Zone are public. If browsers read the files from another origin with `fetch`/XHR, enable CORS headers in the Pull Zone's header settings. Plain `<img>`/`<a>` links don't need CORS.
4. Keep the access key on the server. Browsers can't upload to the Storage API directly, because uploads need the `AccessKey` header. Proxy uploads through your handler.

Valid `region` values (`BunnyStorageSDK.regions.StorageRegion`): `de` (Falkenstein), `uk` (London), `ny` (New York), `la` (Los Angeles), `sg` (Singapore), `se` (Stockholm), `br` (São Paulo), `jh` (Johannesburg), `syd` (Sydney). Any other value throws `unsupported region` at construction.

## Configuration

```ts
import { BunnyStorage } from "@visulima/storage/provider/bunny";

// Minimal: reads BUNNY_STORAGE_ZONE / BUNNY_STORAGE_ACCESS_KEY / BUNNY_STORAGE_REGION
const storage = new BunnyStorage({});
```

```ts
import { BunnyStorage } from "@visulima/storage/provider/bunny";

// Production
const storage = new BunnyStorage({
    zone: process.env.BUNNY_STORAGE_ZONE,
    accessKey: process.env.BUNNY_STORAGE_ACCESS_KEY,
    region: "de",
    publicBaseUrl: "https://cdn.example.com",
    maxUploadSize: "1GB",
    metaStorageConfig: { directory: "/mnt/shared/upload-meta" },
    expiration: { maxAge: "24h", purgeInterval: "1h" },
});
```

| Option              | Type                      | Default                                                                        | Description                                                                                             |
| ------------------- | ------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `zone`              | `string`                  | `BUNNY_STORAGE_ZONE`, then `STORAGE_ZONE`                                      | Storage Zone name. Ignored when `client` is passed.                                                     |
| `accessKey`         | `string`                  | `BUNNY_STORAGE_ACCESS_KEY`, then `BUNNY_ACCESS_KEY`, then `STORAGE_ACCESS_KEY` | Storage Zone password. Ignored when `client` is passed.                                                 |
| `region`            | `BunnyStorageRegion`      | `BUNNY_STORAGE_REGION`, then `STORAGE_REGION`                                  | Main storage region (see the list above). Ignored when `client` is passed.                              |
| `client`            | `StorageZone`             | —                                                                              | A pre-built zone from `BunnyStorageSDK.zone.connect_with_accesskey(...)`.                               |
| `publicBaseUrl`     | `string`                  | —                                                                              | Pull Zone or CDN origin used by `getReadUrl()`. Without it, `getReadUrl()` throws `METHOD_NOT_ALLOWED`. |
| `metaStorageConfig` | `LocalMetaStorageOptions` | OS temp dir (`Upload_meta`)                                                    | `directory` / `prefix` / `suffix` for local metadata files.                                             |

`zone`, `accessKey` and `region` are all required unless you pass `client`. Common options from `BaseStorageOptions` also apply: `maxUploadSize` (`"5TB"`), `allowMIME`, `maxMetadataSize`, `filename`, `fileNameValidation`, `validation`, `expiration`, `metaStorage`, the `on*` hooks, `logger`, `metrics`, `cache`, `retryConfig`, `defaultTimeout`, `defaultSignal` and `useRelativeLocation`.

With a pre-built client:

```ts
import * as BunnyStorageSDK from "@bunny.net/storage-sdk";
import { BunnyStorage } from "@visulima/storage/provider/bunny";

const client = BunnyStorageSDK.zone.connect_with_accesskey(
    BunnyStorageSDK.regions.StorageRegion.Falkenstein,
    process.env.BUNNY_STORAGE_ZONE!,
    process.env.BUNNY_STORAGE_ACCESS_KEY!,
);

const storage = new BunnyStorage({ client, publicBaseUrl: "https://my-pull-zone.b-cdn.net" });
```

## Metadata storage

Upload records are JSON files on **local disk**, by default `<os tmpdir>/Upload_meta/<id>.META`. Bunny has no field for arbitrary metadata.

- On more than one instance, or with an ephemeral `/tmp`, set `metaStorageConfig.directory` to a shared persistent volume, or pass a custom `metaStorage`. Upload locks are held per process.
- Without a record, `get` and `delete` treat the id as the object path.
- Finished uploads **keep** their record. `delete()` removes it.
- `purge()` lists upload **records** (not the zone's files), so expiration only removes this storage's own uploads.

## Behaviour & limits

| Aspect                     | Behaviour                                                                                                                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chunked / resumable writes | ❌ `supportsResumableWrites: false`. Only a whole-file write at offset 0 is accepted. Anything else → `METHOD_NOT_ALLOWED`. The body is buffered in memory.                            |
| Checksums                  | `sha256`. A TUS `Upload-Checksum: sha256 …` is sent to Bunny as its `Checksum` header. If Bunny rejects it, the upload fails with `CHECKSUM_MISMATCH` (TUS 460).                       |
| Range reads                | ❌ `supportsRange: false`.                                                                                                                                                             |
| `getReadUrl()`             | `${publicBaseUrl}/${key}`, unsigned. `expiresIn` is ignored. Without `publicBaseUrl`, or with `responseContentDisposition` / `responseContentType` → `METHOD_NOT_ALLOWED`.             |
| `getUploadUrl()`           | ❌ `METHOD_NOT_ALLOWED`.                                                                                                                                                               |
| `list(limit)`              | **Recursive**: walks the zone's directories breadth-first from `/` until `limit` files are collected (default 1000). Keys are relative to the zone root. Directories are not returned. |
| `copy()` / `move()`        | Copy downloads the object and uploads it again. Move is copy followed by delete.                                                                                                       |
| `delete()`                 | Deleting an object that is already gone counts as success. The adapter only reports an error if the object still exists afterwards.                                                    |
| Custom `filename`          | The returned value becomes the object path (`/<name>`).                                                                                                                                |
| Retries                    | `retryConfig` (default 3 retries, exponential backoff, 408/429/5xx). `signal` / `timeout` are best effort: the SDK can't cancel a request that is already running.                     |

Custom metadata and `cacheControl` are not sent to Bunny. Configure caching on the Pull Zone.

## Using it with the handlers

```ts
// Node
import express from "express";
import { Rest } from "@visulima/storage/handler/http/node";
import { BunnyStorage } from "@visulima/storage/provider/bunny";

const storage = new BunnyStorage({ region: "de", publicBaseUrl: "https://cdn.example.com" });
const app = express();

app.use("/upload", new Rest({ storage }).handle);
```

```ts
// Fetch runtimes
import { Tus } from "@visulima/storage/handler/http/fetch";

const tus = new Tus({ storage });

export default { fetch: (request: Request) => tus.fetch(request) };
```

```ts
// Files facade
import { Files } from "@visulima/storage";

const files = new Files({ adapter: storage });

await files.upload("images/logo.svg", svg, { contentType: "image/svg+xml" });
const url = await files.url("images/logo.svg"); // https://cdn.example.com/images/logo.svg
```

## Troubleshooting

| Symptom                                     | Cause / fix                                                                                    |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `Bunny Storage: missing credentials`        | Set all three: `zone`, `accessKey` and `region` (or the matching environment variables).       |
| `unsupported region "…"`                    | Use one of the region codes listed above. It must be the zone's **main** region.               |
| `403` / `FORBIDDEN` (`Unauthorized access`) | Wrong password, the read-only password, or a region that doesn't match the zone's main region. |
| `400 BAD_REQUEST` (`Unable to upload file`) | An invalid path. With a sha256 checksum it is reported as `CHECKSUM_MISMATCH` instead.         |
| `getReadUrl()` → `405`                      | Set `publicBaseUrl` to a Pull Zone or CDN hostname.                                            |
| Browser `fetch` of the CDN URL fails (CORS) | Enable CORS headers on the Pull Zone.                                                          |
| `405` on a TUS PATCH / chunk                | Send the whole file in one request.                                                            |
