# DigitalOcean Spaces

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage — pick that path when you're hosting an upload server.

## Overview

DigitalOcean Spaces is S3-compatible object storage with an optional built-in CDN. Use [`S3Storage`](./amazon-s3.mdx) (Node.js) or [`AwsLightStorage`](./aws-light.mdx) (edge runtimes). The `digitalOcean()` helper builds the endpoint `https://<region>.digitaloceanspaces.com` and always signs with region `us-east-1`, which is what Spaces expects.

## Installation

```sh
# S3Storage (Node.js)
pnpm add @visulima/storage @aws-sdk/client-s3 @aws-sdk/credential-providers @aws-sdk/s3-request-presigner

# or AwsLightStorage (edge)
pnpm add @visulima/storage aws4fetch
```

## Provider setup

1. **Create a Space** — Control panel → _Spaces Object Storage_ → _Create a Spaces Bucket_. Note its datacenter (`nyc3`, `ams3`, `fra1`, `sgp1`, …); that is the helper's `region`.
2. **Create an access key** — _Spaces Object Storage_ → _Access Keys_ → _Create Access Key_. Prefer **Limited Access** with **Read/Write/Delete** on this bucket over full access. The secret is shown once.
3. **CORS** — needed only when the browser calls Spaces directly (presigned URLs, `clientDirectUpload`). Bucket → _Settings_ → _CORS Configurations_, or with the S3 API:

    ```json
    {
        "CORSRules": [
            {
                "AllowedOrigins": ["https://app.example.com"],
                "AllowedMethods": ["GET", "HEAD", "PUT"],
                "AllowedHeaders": ["*"],
                "ExposeHeaders": ["ETag"],
                "MaxAgeSeconds": 3600
            }
        ]
    }
    ```

4. **Lifecycle** — Spaces accepts S3 lifecycle configuration. Abort multipart uploads this storage didn't start (`purge()` only aborts its own):

    ```json
    {
        "Rules": [{ "ID": "abort-incomplete-mpu", "Status": "Enabled", "Prefix": "", "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 } }]
    }
    ```

    ```sh
    aws s3api put-bucket-lifecycle-configuration --endpoint-url https://nyc3.digitaloceanspaces.com --bucket uploads --lifecycle-configuration file://lifecycle.json
    ```

## Configuration

### `digitalOcean()` helper

`import { digitalOcean } from "@visulima/storage/provider/aws/s3/clients"` returns an `S3ClientConfig` (`credentials`, `endpoint`, `region: "us-east-1"`, `forcePathStyle: false`):

| Parameter | Type     | Required | Env fallback (in order)                  |
| --------- | -------- | -------- | ---------------------------------------- |
| `region`  | `string` | yes      | `AWS_REGION`, `SPACES_REGION`            |
| `key`     | `string` | yes      | `AWS_ACCESS_KEY_ID`, `SPACES_KEY`        |
| `secret`  | `string` | yes      | `AWS_SECRET_ACCESS_KEY`, `SPACES_SECRET` |

`region` only picks the endpoint subdomain. `AWS_REGION` wins over `SPACES_REGION`, so pass `region` explicitly if `AWS_REGION` is set to an AWS region. All other options are the [`S3Storage` options](./amazon-s3.mdx#configuration).

### Minimal

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { digitalOcean } from "@visulima/storage/provider/aws/s3/clients";

const storage = new S3Storage({ bucket: "uploads", ...digitalOcean({ region: "nyc3", key: process.env.SPACES_KEY!, secret: process.env.SPACES_SECRET! }) });
```

### Production

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { digitalOcean } from "@visulima/storage/provider/aws/s3/clients";

const storage = new S3Storage({
    ...digitalOcean({ region: "fra1", key: process.env.SPACES_KEY!, secret: process.env.SPACES_SECRET! }),
    bucket: "uploads",
    acl: "private",
    maxUploadSize: "5GB",
    expiration: { maxAge: "24h", purgeInterval: "1h" },
    logger: console,
});
```

### Edge (`AwsLightStorage`)

```ts
import { AwsLightStorage } from "@visulima/storage/provider/aws-light";

const storage = new AwsLightStorage({
    bucket: "uploads",
    region: "us-east-1",
    endpoint: "https://fra1.digitaloceanspaces.com", // path-style: <endpoint>/<bucket>/<key>
    accessKeyId: process.env.SPACES_KEY!,
    secretAccessKey: process.env.SPACES_SECRET!,
});
```

## Metadata storage

Same as [Amazon S3](./amazon-s3.mdx#metadata-storage): each upload's record is a zero-byte `<id>.META` object in the Space (JSON in the user-metadata header), kept after completion and shared by every instance. `metaStorageConfig: { bucket }` or `{ directory }` moves it. If you make the Space public, the `.META` objects are public too — keep the Space private and serve files through presigned URLs or the CDN with a dedicated prefix.

## Behaviour & limits

See [Amazon S3](./amazon-s3.mdx#behaviour--limits): sequential writes, 5 MiB minimum part size except for the last part, range reads, native `delimiter` listing, presigned URLs with `S3Storage`, `purge()` limited to this storage's uploads.

## Using it with the handlers

```ts
// Node (Express)
import express from "express";
import { Tus } from "@visulima/storage/handler/http/node";

const app = express();

app.use("/files", new Tus({ storage }).handle);
```

```ts
// Fetch
import { Rest } from "@visulima/storage/handler/http/fetch";

const rest = new Rest({ storage });

export default { fetch: (request: Request) => rest.fetch(request) };
```

```ts
// Files facade
import { Files } from "@visulima/storage";

const files = new Files({ adapter: storage });

await files.upload("images/hero.jpg", buffer, { contentType: "image/jpeg" });
const url = await files.url("images/hero.jpg", { expiresIn: 3600 });
```

## Troubleshooting

| Symptom                                  | Cause / fix                                                                                   |
| ---------------------------------------- | --------------------------------------------------------------------------------------------- |
| `403` on missing keys / not ready        | A limited key without access to this bucket, or without list rights. Grant Read/Write/Delete. |
| `SignatureDoesNotMatch`                  | Signing region isn't `us-east-1` (set by the helper), or wrong secret.                        |
| Requests go to the wrong datacenter      | `AWS_REGION` overrode `SPACES_REGION`; pass `region`.                                         |
| Browser CORS errors                      | Add CORS rules for your origin with `PUT`.                                                    |
| `400` "chunks of at least 5 MiB" / `409` | Use a client chunk size ≥ 5 MiB and resume from the offset `HEAD` returns.                    |
