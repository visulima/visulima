# Backblaze B2

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage — pick that path when you're hosting an upload server.

## Overview

Backblaze B2 exposes an S3-compatible API. Use [`S3Storage`](./amazon-s3.mdx) (Node.js) or [`AwsLightStorage`](./aws-light.mdx) (edge runtimes) against B2's S3 endpoint. The `backblaze()` helper builds the endpoint `https://s3.<region>.backblazeb2.com` and maps the application key to S3 credentials.

## Installation

```sh
# S3Storage (Node.js)
pnpm add @visulima/storage @aws-sdk/client-s3 @aws-sdk/credential-providers @aws-sdk/s3-request-presigner

# or AwsLightStorage (edge)
pnpm add @visulima/storage aws4fetch
```

## Provider setup

1. **Create a bucket** — B2 Cloud Storage → _Buckets_ → _Create a Bucket_ (private). The bucket page shows its S3 endpoint, e.g. `s3.us-west-004.backblazeb2.com`; the part between `s3.` and `.backblazeb2.com` is the `region`.
2. **Create an application key** — _Application Keys_ → _Add a New Application Key_. Restrict it to the bucket with **Read and Write** access (that includes listing, reading, writing and deleting files in the bucket). B2 shows the `keyID` and `applicationKey` once. The master key can't be used with the S3 API.
3. **CORS** — needed only when the browser calls B2 directly (presigned URLs, `clientDirectUpload`). Set it with the S3 API (`aws s3api put-bucket-cors --endpoint-url https://s3.<region>.backblazeb2.com --bucket uploads --cors-configuration file://cors.json`):

    ```json
    {
        "CORSRules": [
            {
                "AllowedOrigins": ["https://app.example.com"],
                "AllowedMethods": ["GET", "HEAD", "PUT"],
                "AllowedHeaders": ["*"],
                "ExposeHeaders": ["ETag"],
                "MaxAgeSeconds": 3600
            }
        ]
    }
    ```

    You can also manage the rules under bucket → _CORS Rules_ in the web UI; make sure they cover the S3-compatible API.

4. **Lifecycle** — add a lifecycle rule with `daysFromStartingToCancelingUnfinishedLargeFiles` (bucket → _Lifecycle Settings_ → custom rules) to cancel multipart uploads this storage didn't start; `purge()` only aborts its own.

## Configuration

### `backblaze()` helper

`import { backblaze } from "@visulima/storage/provider/aws/s3/clients"` returns an `S3ClientConfig` (`credentials`, `endpoint`, `region`):

| Parameter          | Type     | Required | Env fallback (in order)                                      |
| ------------------ | -------- | -------- | ------------------------------------------------------------ |
| `region`           | `string` | yes      | `AWS_REGION`, `B2_REGION`, `BACKBLAZE_REGION`                |
| `applicationKeyId` | `string` | yes      | `AWS_ACCESS_KEY_ID`, `B2_APP_KEY_ID`, `BACKBLAZE_APP_KEY_ID` |
| `applicationKey`   | `string` | yes      | `AWS_SECRET_ACCESS_KEY`, `B2_APP_KEY`, `BACKBLAZE_APP_KEY`   |

Note that `AWS_*` variables win over `B2_*` ones: if your environment already has `AWS_REGION` set for AWS, pass `region` explicitly. All other options are the [`S3Storage` options](./amazon-s3.mdx#configuration).

### Minimal

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { backblaze } from "@visulima/storage/provider/aws/s3/clients";

// Reads B2_REGION, B2_APP_KEY_ID, B2_APP_KEY (or the AWS_* equivalents)
const storage = new S3Storage({ bucket: "uploads", ...backblaze() });
```

### Production

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { backblaze } from "@visulima/storage/provider/aws/s3/clients";

const storage = new S3Storage({
    ...backblaze({
        region: "us-west-004",
        applicationKeyId: process.env.B2_APP_KEY_ID!,
        applicationKey: process.env.B2_APP_KEY!,
    }),
    bucket: "uploads",
    maxUploadSize: "5GB",
    expiration: { maxAge: "24h", purgeInterval: "1h" },
    logger: console,
});
```

### Edge (`AwsLightStorage`)

```ts
import { AwsLightStorage } from "@visulima/storage/provider/aws-light";

const storage = new AwsLightStorage({
    bucket: "uploads",
    region: "us-west-004",
    endpoint: "https://s3.us-west-004.backblazeb2.com",
    accessKeyId: process.env.B2_APP_KEY_ID!,
    secretAccessKey: process.env.B2_APP_KEY!,
});
```

## Metadata storage

Same as [Amazon S3](./amazon-s3.mdx#metadata-storage): `<id>.META` zero-byte objects in the bucket hold each upload's record in their user-metadata header. They are skipped by `list()` and `purge()`, survive upload completion, and are shared by every instance using the bucket. `metaStorageConfig: { bucket }` or `{ directory }` moves them.

## Behaviour & limits

See [Amazon S3](./amazon-s3.mdx#behaviour--limits): sequential writes, 5 MiB minimum part size except for the last part, range reads, native `delimiter` listing, presigned URLs with `S3Storage`. B2 keeps earlier versions when you overwrite or delete a file unless the bucket's lifecycle is set to keep only the last version — deleted uploads may still count toward storage until then.

## Using it with the handlers

```ts
// Node (Express)
import express from "express";
import { Tus } from "@visulima/storage/handler/http/node";

const app = express();

app.use("/files", new Tus({ storage }).handle);
```

```ts
// Fetch
import { Rest } from "@visulima/storage/handler/http/fetch";

const rest = new Rest({ storage });

export default { fetch: (request: Request) => rest.fetch(request) };
```

```ts
// Files facade
import { Files } from "@visulima/storage";

const files = new Files({ adapter: storage });

await files.upload("backups/db.sql.gz", buffer, { contentType: "application/gzip" });
```

## Troubleshooting

| Symptom                                  | Cause / fix                                                                                             |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `403` / `InvalidAccessKeyId`             | Master key used, or the key is restricted to another bucket. Create a bucket-scoped Read and Write key. |
| `SignatureDoesNotMatch` / wrong host     | `region` doesn't match the bucket's endpoint (often an `AWS_REGION` from elsewhere). Pass `region`.     |
| Browser CORS errors                      | Add CORS rules that cover the S3-compatible API (see above).                                            |
| `400` "chunks of at least 5 MiB" / `409` | Use a client chunk size ≥ 5 MiB and resume from the offset `HEAD` returns.                              |
