# Tigris

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage — pick that path when you're hosting an upload server.

## Overview

Tigris is globally distributed, S3-compatible object storage. Use [`S3Storage`](./amazon-s3.mdx) (Node.js) or [`AwsLightStorage`](./aws-light.mdx) (edge runtimes). The `tigris()` helper targets `https://t3.storage.dev` with region `auto`.

## Installation

```sh
# S3Storage (Node.js)
pnpm add @visulima/storage @aws-sdk/client-s3 @aws-sdk/credential-providers @aws-sdk/s3-request-presigner

# or AwsLightStorage (edge)
pnpm add @visulima/storage aws4fetch
```

## Provider setup

1. **Create a bucket** — Tigris console → _Create bucket_ (or `fly storage create` on Fly.io, which also prints credentials). Keep it private.
2. **Create an access key** — console → _Access Keys_ → _Create New Access Key_, scoped to the bucket with the **Editor** role. Copy the key ID (`tid_…`) and secret (`tsec_…`).
3. **CORS** — needed only when the browser calls Tigris directly (presigned URLs, `clientDirectUpload`). Set it in the bucket settings or with `aws s3api put-bucket-cors --endpoint-url https://t3.storage.dev`:

    ```json
    {
        "CORSRules": [
            {
                "AllowedOrigins": ["https://app.example.com"],
                "AllowedMethods": ["GET", "HEAD", "PUT"],
                "AllowedHeaders": ["*"],
                "ExposeHeaders": ["ETag"],
                "MaxAgeSeconds": 3600
            }
        ]
    }
    ```

4. **Abandoned multipart uploads** — `purge()` aborts only uploads this storage started; check Tigris's lifecycle support for the rest.

## Configuration

### `tigris()` helper

`import { tigris } from "@visulima/storage/provider/aws/s3/clients"` returns an `S3ClientConfig` (`credentials`, `endpoint`, `region: "auto"`, `forcePathStyle: false`):

| Parameter         | Type     | Required | Env fallback (in order)                                                  |
| ----------------- | -------- | -------- | ------------------------------------------------------------------------ |
| `accessKeyId`     | `string` | yes      | `TIGRIS_ACCESS_KEY_ID`, `TIGRIS_ACCESS_KEY`, `AWS_ACCESS_KEY_ID`         |
| `secretAccessKey` | `string` | yes      | `TIGRIS_SECRET_ACCESS_KEY`, `TIGRIS_SECRET_KEY`, `AWS_SECRET_ACCESS_KEY` |
| `endpoint`        | `string` | no       | `TIGRIS_ENDPOINT`; default `https://t3.storage.dev`                      |

All other options are the [`S3Storage` options](./amazon-s3.mdx#configuration).

### Minimal

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { tigris } from "@visulima/storage/provider/aws/s3/clients";

const storage = new S3Storage({ bucket: "uploads", ...tigris() });
```

### Production

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { tigris } from "@visulima/storage/provider/aws/s3/clients";

const storage = new S3Storage({
    ...tigris({
        accessKeyId: process.env.TIGRIS_ACCESS_KEY_ID!,
        secretAccessKey: process.env.TIGRIS_SECRET_ACCESS_KEY!,
    }),
    bucket: "uploads",
    maxUploadSize: "5GB",
    expiration: { maxAge: "24h", purgeInterval: "1h" },
    logger: console,
});
```

### Edge (`AwsLightStorage`)

```ts
import { AwsLightStorage } from "@visulima/storage/provider/aws-light";

const storage = new AwsLightStorage({
    bucket: "uploads",
    region: "auto",
    // Bucket in the host: virtual-hosted addressing. Use "https://t3.storage.dev" for path-style.
    endpoint: "https://uploads.t3.storage.dev",
    accessKeyId: process.env.TIGRIS_ACCESS_KEY_ID!,
    secretAccessKey: process.env.TIGRIS_SECRET_ACCESS_KEY!,
});
```

## Metadata storage

Same as [Amazon S3](./amazon-s3.mdx#metadata-storage): zero-byte `<id>.META` objects in the bucket hold each upload's record, are skipped by `list()`/`purge()`, kept after completion, and shared by every instance. `metaStorageConfig: { bucket }` or `{ directory }` moves them.

## Behaviour & limits

See [Amazon S3](./amazon-s3.mdx#behaviour--limits): sequential writes, 5 MiB minimum part size except for the last part, range reads, native `delimiter` listing, presigned URLs with `S3Storage`, `purge()` limited to this storage's uploads.

## Using it with the handlers

```ts
// Node (Express)
import express from "express";
import { Tus } from "@visulima/storage/handler/http/node";

const app = express();

app.use("/files", new Tus({ storage }).handle);
```

```ts
// Fetch
import { Rest } from "@visulima/storage/handler/http/fetch";

const rest = new Rest({ storage });

export default { fetch: (request: Request) => rest.fetch(request) };
```

```ts
// Files facade
import { Files } from "@visulima/storage";

const files = new Files({ adapter: storage });

await files.upload("avatars/1.webp", buffer, { contentType: "image/webp" });
const url = await files.url("avatars/1.webp", { expiresIn: 600 });
```

## Troubleshooting

| Symptom                                  | Cause / fix                                                                                         |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `403` / `AccessDenied`                   | The key isn't scoped to this bucket or has a read-only role; use **Editor**.                        |
| `SignatureDoesNotMatch`                  | Region other than `auto`, or wrong secret.                                                          |
| Old endpoint in use                      | Older setups used `fly.storage.tigris.dev`; pass `endpoint` or `TIGRIS_ENDPOINT` if you rely on it. |
| Browser CORS errors                      | Add CORS rules for your origin with `PUT`.                                                          |
| `400` "chunks of at least 5 MiB" / `409` | Use a client chunk size ≥ 5 MiB and resume from the offset `HEAD` returns.                          |
