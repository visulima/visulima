# Cloudflare R2

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage — pick that path when you're hosting an upload server.

## Overview

Cloudflare R2 is S3-compatible object storage with no egress fees. There is no dedicated R2 adapter: you use [`S3Storage`](./amazon-s3.mdx) (AWS SDK v3, Node.js) or [`AwsLightStorage`](./aws-light.mdx) (`aws4fetch`, Workers and other edge runtimes) and point it at your account's R2 endpoint. The `cloudflare()` helper builds that endpoint and the credentials for `S3Storage`.

## Installation

```sh
# S3Storage (Node.js)
pnpm add @visulima/storage @aws-sdk/client-s3 @aws-sdk/credential-providers @aws-sdk/s3-request-presigner

# or AwsLightStorage (Workers / edge)
pnpm add @visulima/storage aws4fetch
```

## Provider setup

1. **Create a bucket** — Dashboard → R2 → _Create bucket_ (or `wrangler r2 bucket create my-bucket`). If you pick a jurisdiction (`eu`, `fedramp`), pass the same `jurisdiction` to the helper: the endpoint changes.
2. **Create an API token** — R2 → _Manage R2 API Tokens_ → _Create API token_. Choose **Object Read & Write** and restrict it to the bucket. Cloudflare shows an _Access Key ID_ and a _Secret Access Key_ once; copy both. Your _Account ID_ is on the R2 overview page.
3. **CORS** — only needed when a browser talks to R2 directly (presigned `PUT` from `getUploadUrl()`, presigned `GET` from `getReadUrl()`, or `clientDirectUpload`). Uploads that go through your own handler don't need it. R2 → bucket → _Settings_ → _CORS policy_:

    ```json
    [
        {
            "AllowedOrigins": ["https://app.example.com"],
            "AllowedMethods": ["GET", "HEAD", "PUT"],
            "AllowedHeaders": ["*"],
            "ExposeHeaders": ["ETag"],
            "MaxAgeSeconds": 3600
        }
    ]
    ```

    `ETag` has to be exposed when the browser uploads multipart parts itself (`clientDirectUpload`).

4. **Lifecycle** — R2 aborts unfinished multipart uploads after 7 days by default; you can change that under bucket → _Settings_ → _Object lifecycle rules_. `purge()` only aborts uploads this storage created (see [Behaviour](#behaviour--limits)), so keep a rule for everything else.

## Configuration

### `cloudflare()` helper

`import { cloudflare } from "@visulima/storage/provider/aws/s3/clients"` returns an `S3ClientConfig` (`credentials`, `endpoint`, `region: "auto"`) to spread into `S3Storage`. Every parameter falls back to environment variables, field by field:

| Parameter         | Type                | Required | Env fallback (in order)                                                          |
| ----------------- | ------------------- | -------- | -------------------------------------------------------------------------------- |
| `accountId`       | `string`            | yes      | `CLOUDFLARE_ACCOUNT_ID`                                                          |
| `accessKeyId`     | `string`            | yes      | `CLOUDFLARE_ACCESS_KEY_ID`, `CLOUDFLARE_ACCESS_KEY`, `AWS_ACCESS_KEY_ID`         |
| `secretAccessKey` | `string`            | yes      | `CLOUDFLARE_SECRET_ACCESS_KEY`, `CLOUDFLARE_SECRET_KEY`, `AWS_SECRET_ACCESS_KEY` |
| `jurisdiction`    | `"eu" \| "fedramp"` | no       | `CLOUDFLARE_JURISDICTION`, `CLOUDFLARE_R2_JURISDICTION`                          |

Resulting endpoint: `https://<accountId>.[<jurisdiction>.]r2.cloudflarestorage.com`. The helper throws `Missing required parameters for Cloudflare R2 client.` when a required value is missing.

All other options (`bucket`, `partSize`, `metaStorageConfig`, `expiration`, `retryConfig`, …) are the [`S3Storage` options](./amazon-s3.mdx#configuration). `bucket` falls back to `S3_BUCKET`.

### Minimal

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { cloudflare } from "@visulima/storage/provider/aws/s3/clients";

// Reads CLOUDFLARE_ACCOUNT_ID, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY
const storage = new S3Storage({ bucket: "my-bucket", ...cloudflare() });
```

### Production

```ts
import { S3Storage } from "@visulima/storage/provider/aws";
import { cloudflare } from "@visulima/storage/provider/aws/s3/clients";

const storage = new S3Storage({
    ...cloudflare({
        accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
        accessKeyId: process.env.R2_ACCESS_KEY_ID!,
        secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
        jurisdiction: "eu",
    }),
    bucket: "uploads",
    maxUploadSize: "5GB",
    allowMIME: ["image/*", "video/*", "application/pdf"],
    expiration: { maxAge: "24h", purgeInterval: "1h" },
    retryConfig: { maxRetries: 5 },
    logger: console,
});
```

### Workers / edge (`AwsLightStorage`)

The helper returns AWS SDK `credentials`, which `AwsLightStorage` doesn't take — pass the fields directly. A custom endpoint is used path-style (`<endpoint>/<bucket>/<key>`), which R2 accepts. `AwsLightStorage` imports `node:stream`, so enable the `nodejs_compat` compatibility flag.

```ts
import { AwsLightStorage } from "@visulima/storage/provider/aws-light";

export default {
    async fetch(request: Request, env: Env): Promise<Response> {
        const storage = new AwsLightStorage({
            bucket: "my-bucket",
            region: "auto",
            endpoint: `https://${env.CLOUDFLARE_ACCOUNT_ID}.r2.cloudflarestorage.com`,
            accessKeyId: env.R2_ACCESS_KEY_ID,
            secretAccessKey: env.R2_SECRET_ACCESS_KEY,
        });

        // ...
    },
};
```

`AwsLightStorage` has no `getReadUrl()` / `getUploadUrl()`; use `S3Storage` if you need presigned URLs.

## Metadata storage

Same as [Amazon S3](./amazon-s3.mdx#metadata-storage): each upload's record is a zero-byte `<id>.META` object in the same bucket, with the JSON in its user-metadata header. `list()` and `purge()` skip those keys, and finished uploads keep their record. Because the records live in the bucket, several server instances share them without extra setup. `metaStorageConfig: { bucket: "uploads-meta" }` moves them to another bucket (same credentials and endpoint); `metaStorageConfig: { directory }` keeps them on local disk, which only works for a single instance.

## Behaviour & limits

Identical to [Amazon S3](./amazon-s3.mdx#behaviour--limits):

- **Sequential, resumable writes** — TUS / chunked REST chunks must arrive in order, and every chunk except the last must be at least 5 MiB (`partSize` defaults to 16 MB). An out-of-order chunk answers `409`.
- **Range reads**, native `list({ delimiter })`, presigned `GET`/`PUT` (`S3Storage` only).
- **`purge()`** removes expired uploads that have metadata from this storage, and aborts only multipart uploads it started.
- R2 ignores canned ACLs; leave `acl` unset and use a public bucket or custom domain for public reads.

## Using it with the handlers

```ts
// Node (Express)
import express from "express";
import { Tus } from "@visulima/storage/handler/http/node";

const app = express();

app.use("/files", new Tus({ storage }).handle);
```

```ts
// Fetch (Workers, Bun, Deno, Hono, …)
import { Rest } from "@visulima/storage/handler/http/fetch";

const rest = new Rest({ storage });

export default { fetch: (request: Request) => rest.fetch(request) };
```

```ts
// Files facade
import { Files } from "@visulima/storage";

const files = new Files({ adapter: storage });

await files.upload("avatars/1.png", buffer, { contentType: "image/png" });
const url = await files.url("avatars/1.png", { expiresIn: 600 });
```

## Troubleshooting

| Symptom                                             | Cause / fix                                                                                                                  |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `403` / storage never becomes ready                 | The token is read-only or scoped to another bucket. Create an **Object Read & Write** token for this bucket.                 |
| `SignatureDoesNotMatch`                             | Wrong secret, or a region other than `auto`. Use the helper or set `region: "auto"`.                                         |
| `NoSuchBucket` although the bucket exists           | The bucket lives in a jurisdiction; pass `jurisdiction` so the endpoint includes it.                                         |
| Browser: "blocked by CORS policy"                   | Add the CORS policy above, with your exact origin and `PUT` for uploads.                                                     |
| `400` "chunks of at least 5 MiB" / `409` on a chunk | Configure the client with a chunk size ≥ 5 MiB and resume from the offset `HEAD` returns instead of re-sending out of order. |
