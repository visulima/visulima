# Firebase Storage

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage.

## Overview

Firebase Storage is a Google Cloud Storage bucket. The adapter resolves a `firebase-admin` app, takes its `Bucket`, and uploads each object in one `file.save()` call. It implements both signed read URLs and signed upload URLs (V4).

## Installation

```sh
npm install firebase-admin
```

```sh
yarn add firebase-admin
```

```sh
pnpm add firebase-admin
```

## Usage

```ts
import { FirebaseStorage } from "@visulima/storage/provider/firebase";

const storage = new FirebaseStorage({
    bucket: "my-project.appspot.com",
    projectId: process.env.FIREBASE_PROJECT_ID,
    credentials: {
        clientEmail: process.env.FIREBASE_CLIENT_EMAIL!,
        privateKey: process.env.FIREBASE_PRIVATE_KEY!,
    },
});
```

Reuse an initialised app (or pass a `@google-cloud/storage` `Bucket` directly) with `app`:

```ts
import { getApp } from "firebase-admin/app";

const storage = new FirebaseStorage({ app: getApp(), bucket: "my-project.appspot.com" });
```

## Configuration

| Option                | Type                          | Description                                                            | Default                                          |
| --------------------- | ----------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------ |
| `bucket`              | `string`                      | Bucket name. Required unless `app` is a `Bucket`                       | `FIREBASE_STORAGE_BUCKET`                        |
| `projectId`           | `string`                      | Google Cloud project id                                                | `FIREBASE_PROJECT_ID` / `GOOGLE_CLOUD_PROJECT`   |
| `credentials`         | `{ clientEmail, privateKey }` | Service-account credentials                                            | `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY` |
| `serviceAccountPath`  | `string`                      | Path to a service-account JSON key                                     | `GOOGLE_APPLICATION_CREDENTIALS`                 |
| `app`                 | `App \| Bucket`               | Pre-built `firebase-admin` app, or a `Bucket` used as-is               | —                                                |
| `appName`             | `string`                      | Named `firebase-admin` app to reuse/create                             | default app                                      |
| `publicBaseUrl`       | `string`                      | `getReadUrl` returns `${publicBaseUrl}/${key}` instead of a signed URL | —                                                |
| `defaultUrlExpiresIn` | `number`                      | Expiry (seconds) for signed URLs                                       | `3600`                                           |
| `metaStorageConfig`   | `LocalMetaStorageOptions`     | Where upload metadata is kept                                          | OS temp directory                                |

## URL Generation

- `getReadUrl(key, { expiresIn, responseContentDisposition, responseContentType })` — V4 signed `GET`. With `publicBaseUrl` set it returns the public URL instead, and the response overrides are rejected with `BAD_REQUEST`.
- `getUploadUrl(key, { expiresIn, contentType })` — V4 signed `PUT`. `contentLength` is rejected with `BAD_REQUEST` (a signed PUT can't enforce it).

## Limitations

- Uploads are single-shot: the part is buffered and saved in one request, so resumable/chunked uploads (TUS, chunked REST) must send the whole file in one request. Use `getUploadUrl()` for large direct-from-client transfers.
- Per-operation `signal` / `timeout` are best-effort: the SDK can't cancel an in-flight request. `retries` is honoured.
