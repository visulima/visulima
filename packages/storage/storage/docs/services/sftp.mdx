# SFTP

> **Just need ad-hoc uploads?** Wrap this adapter in the [`Files` facade](../files-facade.mdx) for a one-liner API. The reference below shows direct adapter usage.

## Overview

The SFTP adapter (built on `ssh2-sftp-client`) maps keys onto remote paths under `rootFolderPath`. SFTP has no metadata store, so upload metadata is kept as sidecar JSON on the local disk. A fresh connection is opened and closed around every operation; the SSH channel isn't safe for concurrent use, so the adapter doesn't pool connections.

## Installation

```sh
npm install ssh2-sftp-client
```

```sh
yarn add ssh2-sftp-client
```

```sh
pnpm add ssh2-sftp-client
```

## Usage

```ts
import { readFileSync } from "node:fs";

import { SftpStorage } from "@visulima/storage/provider/sftp";

const storage = new SftpStorage({
    connection: {
        host: "sftp.example.com",
        username: "deploy",
        privateKey: readFileSync("/path/to/id_ed25519"),
    },
    rootFolderPath: "uploads",
});
```

## Configuration

| Option              | Type                      | Description                                                                                               | Default             |
| ------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------- |
| `connection`        | `ConnectOptions`          | `ssh2-sftp-client` connection options (`host`, `port`, `username`, `password`, `privateKey`, …). Required | —                   |
| `rootFolderPath`    | `string`                  | Remote directory acting as the bucket root; intermediate directories are created on write                 | connection home dir |
| `metaStorageConfig` | `LocalMetaStorageOptions` | Where the sidecar metadata is kept                                                                        | OS temp directory   |

## Behaviour

- **Ranged reads** — `supportsRange` is `true`, so `download({ range })` reads only the requested bytes.
- **Single-shot writes** — each object is uploaded in one request. A chunk that doesn't start at offset 0, or doesn't carry the whole file, is **rejected with `METHOD_NOT_ALLOWED`** rather than written (writing it would overwrite the earlier bytes or leave a truncated file). Resumable/chunked uploads (TUS, chunked REST) must send the whole file in one request.
- **No URLs** — `getReadUrl()` / `getUploadUrl()` reject with `METHOD_NOT_ALLOWED`; SFTP has no signed-URL concept.
- `write()` buffers the part in memory before uploading.
