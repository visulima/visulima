# Error Handling

Visulima storage provides consistent error handling across all storage backends with standardized error codes and messages.

## Error Types

Storage and handler code throws two kinds of errors:

- **`UploadError`** — operational failures (not found, locked, read-only, unsupported operation, …). It carries `UploadErrorCode` (an `ERRORS` value), `message` and an optional `detail` with the original provider error. It has **no** `statusCode`; map the code to a status with `ErrorMap[error.UploadErrorCode].statusCode`.
- **`ValidationError`** — a file failed one of the adapter's validators (`maxUploadSize`, `allowMIME`, file name, or your own `validation` rules). It has `name === "ValidationError"`, `code` (the validator's key: `"size"`, `"mime"`, `"filename"` or your rule name), `statusCode` (413, 415, 400, …), `body` and `headers`. The package exports its type, not the class, so detect it by `name`.

### Upload Errors

```typescript
import { ErrorMap, ERRORS, isUploadError } from "@visulima/storage";

try {
    await storage.get({ id: "nonexistent" });
} catch (error) {
    if (isUploadError(error)) {
        console.log("Error code:", error.UploadErrorCode); // e.g. "FileNotFound"
        console.log("Status:", ErrorMap[error.UploadErrorCode]?.statusCode); // e.g. 404
        console.log("Message:", error.message);
        console.log("Provider error:", error.detail);
    }
}
```

## Error Response Format

The HTTP handlers turn every error into an `HttpError` (`{ code, message, statusCode, name?, headers?, body? }`), pass it to the storage's `onError` hook, and send it as JSON:

```json
{ "error": { "code": "FileNotFound", "message": "Not found", "name": "Error" } }
```

Errors the handler does not recognise (anything that is not an `UploadError`, `ValidationError` or `http-errors` error) go through `storage.normalizeError()`; when that yields a 5xx status (the usual case), the client gets the generic message `"Something went wrong"`, so paths and SDK messages never reach it. `onError` still receives the original message and details, so log them there. If `onError` sets `body`, that body is sent as-is, so keep internals out of it.

## Handling Common Errors

### File Not Found

```typescript
try {
    await storage.get({ id: "nonexistent" });
} catch (error) {
    if (isUploadError(error) && error.UploadErrorCode === ERRORS.FILE_NOT_FOUND) {
        return res.status(404).json({ error: "File not found" });
    }
    throw error;
}
```

### Validation Failures (File Too Large, Unsupported Media Type, …)

`storage.create()` runs the validators and throws a `ValidationError`, not an `UploadError`:

```typescript
import type { ValidationError } from "@visulima/storage";

const isValidationError = (error: unknown): error is ValidationError => (error as { name?: string })?.name === "ValidationError";

try {
    await storage.create({
        contentType: "application/x-executable",
        size: 100 * 1024 * 1024, // 100MB
    });
} catch (error) {
    if (isValidationError(error)) {
        // error.code: "size" → 413, "mime" → 415, "filename" → 400, or your own rule name
        return res.status(error.statusCode).json({ error: error.message, rule: error.code });
    }
    throw error;
}
```

### Checksum Mismatch

```typescript
try {
    await storage.write({
        id: "file-id",
        start: 0,
        body: stream,
        checksum: "invalid-checksum",
        checksumAlgorithm: "md5",
    });
} catch (error) {
    if (isUploadError(error) && error.UploadErrorCode === ERRORS.CHECKSUM_MISMATCH) {
        return res.status(460).json({ error: "Checksum mismatch" });
    }
    throw error;
}
```

## Custom Error Handling

### Custom Error Responses

`onError` returns nothing; it customises the response by mutating the `HttpError` it receives. Setting `body` replaces the default `{ error: { … } }` JSON:

```typescript
import { DiskStorage } from "@visulima/storage";
import type { HttpError } from "@visulima/storage";

const storage = new DiskStorage({
    directory: "./uploads",
    onError: (error: HttpError) => {
        // The original message is still available here, even for 500s the client only sees as "Something went wrong"
        logger.error(error);

        error.body = {
            code: error.code,
            message: error.statusCode >= 500 ? "Upload failed" : error.message,
            timestamp: new Date().toISOString(),
        };
        error.headers = { ...error.headers, "X-Error-Code": String(error.code) };
    },
});
```

### Error Logging

```typescript
const storage = new DiskStorage({
    directory: "./uploads",
    logger: {
        error: (message, ...args) => {
            console.error(`[Storage Error] ${message}`, ...args);
            // Send to error tracking service
            errorTracker.captureException(new Error(message));
        },
        debug: (message, ...args) => {
            console.debug(`[Storage Debug] ${message}`, ...args);
        },
        info: (message, ...args) => {
            console.info(`[Storage Info] ${message}`, ...args);
        },
    },
});
```

## Error Middleware

### Express Error Middleware

The HTTP handlers answer their own errors. This middleware is for errors your own code throws (e.g. a route that calls the adapter directly):

```typescript
import { ErrorMap, isUploadError } from "@visulima/storage";

app.use((error: Error, req: express.Request, res: express.Response, next: express.NextFunction) => {
    if (isUploadError(error)) {
        const statusCode = ErrorMap[error.UploadErrorCode]?.statusCode ?? 500;
        return res.status(statusCode).json({
            error: {
                code: error.UploadErrorCode,
                message: error.message,
            },
        });
    }

    // Handle other errors
    res.status(500).json({ error: "Internal server error" });
});
```

### Hono Error Handler

```typescript
app.onError((error, c) => {
    if (isUploadError(error)) {
        return c.json(
            {
                error: {
                    code: error.UploadErrorCode,
                    message: error.message,
                },
            },
            (ErrorMap[error.UploadErrorCode]?.statusCode ?? 500) as ContentfulStatusCode,
        );
    }

    return c.json({ error: "Internal server error" }, 500);
});
```

## Best Practices

1. **Always check error types** - Use `isUploadError()` for operational errors and `error.name === "ValidationError"` for validator failures
2. **Handle specific error codes** - Provide user-friendly messages for common errors
3. **Log errors appropriately** - Include context for debugging
4. **Return appropriate status codes** - Use standard HTTP status codes
5. **Don't expose internal details** - Sanitize error messages for production
