# API: Types

TypeScript type definitions for Cerebro.

## Core Types

### Cli

Main CLI class interface:

```typescript
interface Cli {
    addCommand(command: Command): this;
    addPlugin(plugin: Plugin): this;
    run(options?: CliRunOptions): Promise<void>;
    runCommand(commandName: string, options?: RunCommandOptions): Promise<unknown>;
    setDefaultCommand(commandName: string): this;
    setCommandSection(section: CommandSection): this;
    getCliName(): string;
    getCommands(): Map<string, Command>;
    getCwd(): string;
    getPackageName(): string | undefined;
    getPackageVersion(): string | undefined;
    getPluginManager(): PluginManager;
    dispose(): void;
}
```

### Command

Command definition. Either `execute` or `loader` must be set — not both.

```typescript
interface Command<O extends OptionDefinition = OptionDefinition, TContext extends Toolbox = Toolbox> {
    name: string;
    execute?: (toolbox: TContext) => Promise<void> | void;
    loader?: () => Promise<LazyCommandModule<TContext>>;
    description?: string;
    alias?: string | string[];
    argument?: ArgumentDefinition;
    options?: OptionDefinition[];
    env?: EnvDefinition[];
    hidden?: boolean;
    group?: string;
    examples?: string[] | string[][];
    usage?: Content[];
    file?: string;
    commandPath?: string[];
}
```

### CommandExecute

Handler signature, used by both `execute` and the resolved default export of `loader`.

```typescript
type CommandExecute<TContext> = ((toolbox: TContext) => Promise<void>) | ((toolbox: TContext) => void);
```

### LazyCommandModule

Module shape returned by a command `loader`.

```typescript
interface LazyCommandModule<TContext> {
    default: CommandExecute<TContext>;
}
```

### Plugin

Plugin definition:

```typescript
interface Plugin {
    name: string;
    description?: string;
    version?: string;
    dependencies?: string[];
    init?: (context: PluginContext) => Promise<void> | void;
    execute?: (toolbox: Toolbox) => Promise<void> | void;
    beforeCommand?: (toolbox: Toolbox) => Promise<void> | void;
    afterCommand?: (toolbox: Toolbox, result: unknown) => Promise<void> | void;
    onError?: (error: Error, toolbox: Toolbox) => Promise<void> | void;
}
```

### Toolbox

Command execution context:

```typescript
interface Toolbox<T extends Console = Console> extends Cerebro.ExtensionOverrides {
    argument: string[];
    argv: Record<string, any>;
    command: Command;
    commandName: string;
    logger: T;
    options: Options;
    runtime: Cli;
}
```

### Record Forms

`options` and `env` can each be given as a record keyed by name instead of an
array. The key is the name, so `name` is omitted from the value:

```typescript
type OptionDefinitionRecord = Record<string, Omit<OptionDefinition<unknown>, "name">>;
type EnvDefinitionRecord = Record<string, Omit<EnvDefinition<unknown>, "name">>;
```

`arguments` has no record form — slot order is load-bearing, and an alphabetical
object-key sorter would silently renumber the positionals.

`CommandInput` is the shape `addCommand` accepts — `Command` with those two fields
widened to accept either form. `addCommand` normalizes them to arrays, so `Command`
(and `toolbox.command`) always holds the array form.

## Inference Types

Used by [`defineCommand`](/docs/cerebro/guides/options#type-inference-with-definecommand)
to derive the toolbox shape from the definitions themselves:

```typescript
type InferOptions<R extends OptionDefinitionRecord>; // → toolbox.options
type InferEnv<R extends EnvDefinitionRecord>; // → toolbox.env
type InferArguments<T extends readonly ArgumentDefinition[]>; // → toolbox.args
```

`InferArguments` reads a tuple; `defineCommand` captures it with a `const` type
parameter, so no `as const` is needed at the call site.

Options and positionals share one fold — a hyphen folds into the next character
only when it is an ASCII lowercase letter, transcribed from the parser's
`/-([a-z])/g`. Environment variables lowercase first instead, which is what
`OptionNameToCamelCase` (and `CreateOptions` / `CreateEnv`) model.

```typescript
type Options = InferOptions<{
    "output-dir": { type: StringConstructor; required: true };
    verbose: { type: BooleanConstructor };
}>;
// { outputDir: string; verbose: boolean | undefined }
```
