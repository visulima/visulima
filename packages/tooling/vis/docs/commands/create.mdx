# vis create

Create a new project from a template. Supports built-in templates, npm `create-*` packages, and git repository templates from GitHub, GitLab, Bitbucket, and Sourcehut.

When run without arguments in a terminal, launches an interactive wizard.

## Usage

```bash
vis create [template] [name] [-- template-args...]
```

## Examples

```bash
# Interactive mode (guided wizard)
vis create

# Built-in templates
vis create vis:monorepo my-workspace
vis create vis:app my-app
vis create vis:library my-lib
vis create vis:generator my-gen

# npm create-* packages
vis create vite my-app
vis create vite my-app -- --template react-ts
vis create next-app my-app
vis create svelte my-app

# Git repositories
vis create user/repo my-project
vis create github:user/repo
vis create gitlab:company/templates/node-service
vis create bitbucket:team/starter
vis create https://github.com/user/repo/tree/main/packages/template

# Organization templates (picker over @acme/create's manifest)
vis create @acme
vis create @acme:service my-svc

# Show available templates
vis create --list
```

## Options

| Option             | Default | Description                                   |
| ------------------ | ------- | --------------------------------------------- |
| `--list`           | `false` | Show available templates and config aliases   |
| `--editor`         |         | Generate editor configs (`vscode`)            |
| `--git-init`       | `false` | Initialize a git repository after scaffolding |
| `--no-interactive` | `false` | Skip interactive prompts                      |

## Built-in Templates

| Template        | Description                                              |
| --------------- | -------------------------------------------------------- |
| `vis:monorepo`  | Full pnpm workspace with `apps/` and `packages/` dirs    |
| `vis:app`       | Application scaffold via `create-vite`                   |
| `vis:library`   | TypeScript library with exports, vitest, and tsconfig    |
| `vis:generator` | Code generator with `bin/` entry point and `src/` layout |

## Git Repository Templates

Templates can be downloaded from any git host using [giget](https://github.com/unjs/giget):

| Format                 | Example                                        |
| ---------------------- | ---------------------------------------------- |
| GitHub shorthand       | `user/repo`                                    |
| GitHub with branch     | `user/repo#dev`                                |
| GitHub subdirectory    | `user/repo/tree/main/packages/template`        |
| GitLab                 | `gitlab:group/repo`                            |
| GitLab nested groups   | `gitlab:group/subgroup/repo`                   |
| Self-hosted GitLab     | `gitlab://git.example.com/group/repo`          |
| Bitbucket              | `bitbucket:team/repo`                          |
| Sourcehut              | `sourcehut:~user/repo`                         |
| Full URL (known hosts) | `https://gitlab.com/group/repo`                |
| Host without scheme    | `github.com/user/repo`, `git.sr.ht/~user/repo` |
| SSH (any host)         | `git@git.example.com:group/repo`               |
| Forced SSH clone       | `git:git@github.com:user/repo`                 |
| Tarball URL            | `https://example.com/templates/starter.tar.gz` |

Full URLs and `host/owner/repo` forms for GitHub, GitLab, Bitbucket, and Sourcehut are rewritten to the matching provider before download, and `tree/<ref>/<subdir>` paths become a subdirectory plus a ref. Any other `https://` URL is treated as a tarball.

`git@host:group/repo` on a host other than GitHub, GitLab.com, Bitbucket, or Sourcehut clones over SSH with your own git credentials (keys or agent), which is the way to reach other private or self-hosted servers. On the four known hosts the same form downloads an archive with the host's token; prefix it with `git:` (`git:git@github.com:user/repo`) to force an SSH clone. Self-hosted GitLab (`gitlab://host/…`) downloads the repository archive over HTTPS from that host. `GITLAB_TOKEN` is not sent there, since it belongs to gitlab.com; for a private project set `create.auth` or `GIGET_AUTH`, or put a token in the URL.

### Private Repositories

Set environment variables to authenticate with private repos:

```bash
# GitHub
export GITHUB_TOKEN=ghp_...

# GitLab
export GITLAB_TOKEN=glpat-...

# Bitbucket
export BITBUCKET_TOKEN=...
```

Each token is only sent to its own host: `GITHUB_TOKEN` (or `GH_TOKEN`) to GitHub, `GITLAB_TOKEN` to GitLab, `BITBUCKET_TOKEN` to Bitbucket. Tarball URLs receive no token unless you set `create.auth` or `GIGET_AUTH`.

Or pass a token inline via URL:

```bash
vis create https://ghp_token@github.com/private-org/template
```

## Template Arguments

Arguments after `--` are forwarded to the template runner:

```bash
vis create vite my-app -- --template react-ts
vis create next-app my-app -- --typescript --eslint
```

## Interactive Mode

When run without arguments in a TTY, an interactive wizard guides you through:

1. **Template selection** — choose from built-in templates or enter a custom one
2. **Project name** — with a random suggestion and npm validation
3. **Target directory** — with conflict detection and overwrite confirmation
4. **Package manager** — pnpm, npm, yarn, or bun (standalone projects only)
5. **Git init** — initialize a git repository (standalone only)
6. **Editor config** — generate VS Code settings and extensions

## Post-Creation Tasks

After scaffolding, vis automatically:

1. **Editor config** — Creates `.vscode/settings.json` and `extensions.json` (when `--editor=vscode`)
2. **AI instructions** — Creates `.ai/instructions` (skipped if already provided by template)
3. **Git init** — Runs `git init` (when `--git-init`, standalone projects only)
4. **Install dependencies** — Runs the detected package manager's install command

## Configuration

Configure defaults in `vis.config.ts`:

```ts
import { defineConfig } from "@visulima/vis/config";

export default defineConfig({
    create: {
        // Skip the PM prompt — always use pnpm
        defaultPm: "pnpm",

        // A bare `vis create` opens the picker for this organization's templates
        defaultTemplate: "@acme",

        // Auto-generate VS Code config
        defaultEditor: "vscode",

        // Auto-init git for standalone projects
        gitInit: true,

        // Disable automatic dependency installation
        install: false,

        // Prefer cached templates (faster, works offline)
        preferOffline: true,

        // Auth token for private repository templates
        auth: "ghp_...",

        // Custom template registry
        registry: "https://my-registry.example.com",

        // Named aliases for quick access
        templates: {
            react: "github:vitejs/vite/packages/create-vite/template-react-ts",
            lib: "github:my-org/lib-template",
            internal: "gitlab:company/templates/node-service",
        },
    },
});
```

### Template Aliases

When `create.templates` is configured, use alias names directly:

```bash
vis create react my-app     # → github:vitejs/vite/packages/create-vite/template-react-ts
vis create internal my-svc  # → gitlab:company/templates/node-service

# Show all aliases
vis create --list
```

`create.defaultTemplate` sets the template for a bare `vis create`. Any template input works, including an organization (`"@acme"` or `"@acme:app"`). In a terminal the other prompts (name, directory, package manager, and so on) still run, minus the template step.

## Organization Templates

An organization can publish its own set of templates under its npm scope. `vis create @acme` resolves the package `@acme/create`:

- If it declares a `createConfig.templates` manifest, vis shows a picker over the templates and runs the chosen one.
- If it has no manifest, `@acme` runs `@acme/create` as an ordinary create-\* package, exactly as before.

```bash
vis create @acme                  # picker in a terminal; lists the templates and exits in CI
vis create @acme:service my-svc   # run one entry directly, no picker
vis create @acme --list           # print the templates
```

### Authoring `@acme/create`

Add a `createConfig.templates` array to the package's `package.json`:

```json
{
    "name": "@acme/create",
    "version": "1.0.0",
    "createConfig": {
        "templates": [
            { "name": "app", "description": "Web app with our defaults", "source": { "kind": "npm", "package": "@acme/create-app" } },
            { "name": "service", "description": "Node service", "source": { "kind": "git", "url": "github:acme/service-template" } },
            { "name": "lib", "description": "Shared library", "source": { "kind": "bundled", "path": "templates/lib" } }
        ]
    }
}
```

The map form is also accepted: `"templates": { "app": { "description": "...", "source": { ... } } }`.

Each entry has a `name`, a `description`, and a `source`. The source kinds are:

| `source.kind` | Field     | Behaviour                                                                                                                                                                                |
| ------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm`         | `package` | A package name without a version or flags, run like `vis create <package>`. It is used as written, without the `create-` shorthand expansion.                                            |
| `git`         | `url`     | A `github:`, `gitlab:`, `bitbucket:` or `sourcehut:` source (host URLs for those providers also work). Downloaded like any git template. Raw `git:` clones and tarball URLs are refused. |
| `bundled`     | `path`    | A directory inside `@acme/create`, copied out of the published tarball. The path is relative and made of plain segments. Symlinks are not copied.                                        |

Validation is strict, because the manifest comes from the registry:

- At most 50 templates. Names are unique, at most 64 characters, match `[a-z0-9][a-z0-9._-]*`, and cannot contain `/`, `\`, `:`, or a leading `_`, `-` or `.`.
- Descriptions are 1 to 200 characters. Control characters are removed.
- An invalid manifest fails the command. vis does not fall back to running `@acme/create`.

The manifest is read from the registry configured for the `@acme` scope in `.npmrc`, falling back to the public npm registry, and uses the same `_authToken` you use for `npm install`. Bundled templates download the package tarball without credentials, so they need a publicly downloadable package.

## Monorepo Awareness

When run inside an existing monorepo workspace:

- **vis:monorepo** is hidden from the interactive template list (prevents nesting)
- Applications are placed in `apps/` and libraries in `packages/` automatically
- The package manager prompt is skipped (uses the workspace PM)
- Git init is skipped (the workspace already has git)
